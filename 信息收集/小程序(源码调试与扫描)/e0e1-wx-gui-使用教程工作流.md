# e0e1-wx-gui 使用教程

## 前置条件

- 微信已登录桌面版
- 目标小程序已打开过至少一次(工具需要检测到本地缓存)
- 已完成部署,能正常执行 `python main.py` 打开图形界面

## 一、启动程序

```powershell
cd E:\tools\recon\e0e1-wx
.\.venv\Scripts\Activate.ps1
python main.py
```

启动后会看到主界面,顶部一排功能按钮:反编译源代码开关、是否优化代码开关、JS 文件注入、MCP、Config 配置、正则规则、加密解密。中间是"小程序监控区域"。

## 二、监控功能(第一步,几乎所有操作的起点)

1. 保持程序运行,打开微信里任意一个小程序
2. 程序会自动检测到该小程序,在"小程序监控区域"生成一张卡片
3. 卡片会持续显示存活状态,如果小程序有分包,也会一并记录
4. 关闭小程序后,卡片会显示为"已关闭",可以用右上角"批量删除已关闭"清理

这一步是后续所有分析动作的基础——反编译、DevTools、路由、云函数都是针对这里监控到的小程序卡片操作的。

## 三、反编译与代码搜索

1. 在监控到的小程序卡片上,点第一个按钮开启**自动化反编译**
2. 反编译完成后,点第二个按钮对代码做**格式化整理**,方便阅读
3. 反编译结果可以直接在界面里查看

常用辅助功能:

- `Ctrl + F`:在反编译后的文件内搜索,支持高亮结果
- **自动正则匹配**:程序会按 config.yaml 里配置的正则规则(比如 Google API Key、Firebase 密钥格式等)自动扫描敏感信息
- 双击匹配结果可以直接跳转到对应文件的具体位置
- **全局搜索**:支持普通关键词搜索和正则搜索,可以跨文件查找

## 四、DevTools CDP(浏览器调试)

用于把小程序调试链路接到浏览器里,方便用浏览器的开发者工具做更深入分析。

步骤:

1. 点击"开始调试"
2. 重新打开或重启目标小程序
3. 等待工具与小程序回连
4. 复制生成的调试链接,粘贴到浏览器打开

## 五、路由功能

可以接管小程序的路由信息,在列表里选中目标路由,直接跳转打开对应页面,不用在小程序里手动一层层点进去。

## 六、云函数功能

- 程序支持**静态扫描**(从反编译代码里找出云函数定义)和**动态捕获**(运行时抓取实际调用)
- 双击某个云函数,点击"手动调用"即可单独测试这个云函数,验证输入输出

## 七、调试开关(快速开启 vConsole)

如果只是想快速打开小程序自带的调试面板(vConsole),不需要走完整 DevTools CDP 流程:

1. 点击"开始调试"
2. 关闭当前小程序
3. 从小程序列表重新打开目标小程序
4. 等待 `vConsole` 面板出现

关闭方式两种:通过调试面板本身关闭,或通过工具里的对应入口关闭。

## 八、跳转功能(扩展攻击面)

用途:通过一个小程序反编译出的 appid,发现并跳转到其他关联小程序,扩大测试范围。

1. 反编译后留意代码里出现的其他 appid 标识
2. 在"跳转功能"页面填入 appid:
   - **只填 appid(不带 path)**:点"立即跳转",工具会列出该小程序的功能点,点击某个功能点即可跳转进入对应小程序
   - **appid + path**:直接跳转到该小程序的指定页面

## 九、MCP 自动化渗透(进阶)

1. 在主页开启 MCP
2. 在目标小程序里开启调试,重启小程序完成回连
3. 让 MCP 读取项目里的 `SKILL.md`,即可实现自动化辅助渗透流程

## 十、抓包/代理场景下的注意事项

如果你同时开了抓包工具、系统代理或流量转发工具,可能导致 DevTools 的 `ws` 连接被转发而回连失败。

解决办法(以 Proxifier 为例),给微信小程序相关进程单独加一条直连规则:

```
应用程序:WeChatApp.exe; WechatBrowser.exe; WeChatAppEx.exe
目标主机:127.0.0.1; localhost; ::1
动作:Direct
```

如果你已经有自己的抓包规则,保留原规则,额外加这一条本地回环直连规则即可。

## 建议的使用顺序

1. 启动程序 → 打开小程序 → 确认监控卡片生成
2. 反编译 → 格式化 → 全局搜索/正则匹配,先看有没有明显的敏感信息泄露
3. 需要动态调试就走 DevTools CDP 或调试开关(vConsole)
4. 需要测试后端接口就用云函数功能
5. 想扩大测试范围,再用跳转功能顺藤摸瓜找关联小程序
