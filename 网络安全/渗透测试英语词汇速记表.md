# 渗透测试英语词汇速记表

专为集中记忆设计，分四大块：**网站目录/路径词汇**、**渗透相关代码函数词汇**、**常见攻击术语**、**常用工具/软件**。对有安全意义的词条，额外补充了"看到这个词该联想到什么审计动作"；安全意义不大的词条（如纯展示类的 `img`/`css`）保持简洁，不做过度展开。

---

## 一、网站目录 / 路径常见英文单词

> 渗透测试中做目录扫描（如 dirsearch、御剑）时，字典里全是这些词，认得越多，扫描结果看一眼就知道哪个路径有价值。

| 英文                               | 中文                  | 记忆提示                                                         |
| -------------------------------- | ------------------- | ------------------------------------------------------------ |
| `admin` / `administrator`        | 管理员                 | 后台入口最常见路径                                                    |
| `login` / `signin`               | 登录                  | 核心爆破/弱口令测试入口，也是找 SQL 注入、逻辑绕过的高频位置                            |
| `logout` / `signout`             | 登出                  | 可测试登出后 Session/Token 是否真正失效（常见"登出不彻底"逻辑漏洞）                   |
| `register` / `signup`            | 注册                  | 可批量注册测试验证码绕过、短信炸弹、用户名枚举                                      |
| `upload`                         | 上传                  | 文件上传功能常用目录名，直接对应"任意文件上传"漏洞测试点                                |
| `download`                       | 下载                  | 配合参数遍历可测试"任意文件下载/路径穿越"                                       |
| `config` / `configuration`       | 配置                  | 常含数据库账号密码等敏感信息，是信息泄露类漏洞的重点目标路径                               |
| `backup`                         | 备份                  | 常见 `.bak`、`.zip` 源码泄露路径，扫描字典里优先级很高                           |
| `test` / `testing`               | 测试                  | 测试环境/测试账号常见目录，往往权限校验被临时弱化或遗留后门                               |
| `dev` / `development`            | 开发                  | 开发环境，往往防护较弱、可能遗留调试接口/详细报错信息                                  |
| `api`                            | 接口                  | Application Programming Interface 的缩写；API 路径是接口测试和未授权访问的核心目标 |
| `static`                         | 静态资源                | 图片/CSS/JS 等不常变化的文件；但静态目录下误放的敏感文件常被忽视扫描                       |
| `assets`                         | 资源                  | 同上，前端打包后常见目录名，同样要注意是否混入了不该公开的文件                              |
| `includes`                       | 包含文件                | PHP 项目中常放被 `include` 的公共文件，是文件包含漏洞（LFI）常见的目标路径               |
| `uploads`                        | 上传目录（复数）            | 存放用户上传的实际文件，拿到上传路径后常直接尝试访问已上传的 Webshell                      |
| `data`                           | 数据                  | 可能直接存放数据库导出文件、用户数据文件，属于信息泄露排查点                               |
| `db` / `database`                | 数据库                 | 常见数据库配置文件/备份文件所在目录名，泄露即可能拿到数据库凭证                             |
| `log` / `logs`                   | 日志                  | 可能泄露报错堆栈、路径信息，还可配合"日志投毒"实现文件包含转代码执行                          |
| `temp` / `tmp`                   | 临时文件                | 文件上传/生成过程中的临时存放点，有时能捡到遗留的敏感临时文件                              |
| `cache`                          | 缓存                  | 缓存文件可能保留了已渲染的敏感页面内容，也是"缓存投毒"相关的排查点                           |
| `vendor`                         | 第三方依赖               | PHP Composer / 前端第三方库常用目录名，出现即可判断技术栈，便于匹配已知组件漏洞              |
| `node_modules`                   | Node.js 依赖包目录       | 出现即可判断目标用了 Node.js，切换到 Node.js 专属审计思路（RCE/原型链污染等）            |
| `public`                         | 公开目录                | 对外暴露的根目录，正常；但要留意是否有本该私有的文件被放进了这里                             |
| `private`                        | 私有目录                | 本不该对外暴露，若能直接访问到，本身就是越权访问类漏洞                                  |
| `src`                            | 源码（source 缩写）       | 若能直接访问（如未正确部署、配置错误），等同于直接拿到源码                                |
| `dist`                           | 构建产物（distribute 缩写） | 前端打包编译后的目录，排查是否误带了 Source Map（见 Webpack 笔记）                  |
| `install`                        | 安装                  | 安装向导页面，若未删除可能被重新初始化系统，甚至重置管理员账号                              |
| `setup`                          | 安装/设置               | 同上，是"二次安装/重置"类漏洞的典型路径                                        |
| `manage` / `manager`             | 管理                  | 后台管理入口的常见变体写法，补充到后台路径字典中很有用                                  |
| `panel`                          | 面板                  | 常见于"管理面板"`admin panel`，同样是后台入口变体                             |
| `dashboard`                      | 仪表盘                 | 后台首页常见叫法，登录后台成功后的落地页，可作为判断登录是否成功的标志                          |
| `user` / `users`                 | 用户                  | 常见越权访问点，如 `/user/123` 改 ID 测试水平越权（IDOR）                      |
| `account`                        | 账户                  | 同上，常与个人信息修改、密码重置等敏感操作关联                                      |
| `profile`                        | 个人资料                | 常见存储/展示其他用户隐私信息的位置，IDOR 重点测试对象                               |
| `settings`                       | 设置                  | 可能包含越权修改他人配置、权限提升的操作入口                                       |
| `search`                         | 搜索                  | 搜索框常是注入点（SQL 注入、XSS 反射型常在搜索结果页触发）                            |
| `export` / `import`              | 导出 / 导入             | 导出功能常可批量拉取敏感数据（越权导出）；导入功能常是反序列化/文件解析漏洞入口                     |
| `file` / `files`                 | 文件                  | 文件相关操作的通用目录名，直接关联上传/下载/读取/包含全链路审计点                           |
| `img` / `image` / `images`       | 图片                  | 低相关性，一般为静态资源展示                                               |
| `js` / `javascript`              | JS 脚本               | 低相关性，但可结合前文"JS 安全结合点"去读代码本身                                  |
| `css` / `style` / `styles`       | 样式                  | 低相关性，纯展示用途                                                   |
| `doc` / `docs` / `documentation` | 文档                  | 低相关性，但有时能意外暴露内部 API 文档（接口未授权访问的信息源）                          |
| `old`                            | 旧版本                 | 常见遗留文件/旧版本接口，往往校验逻辑比新版本弱，是绕过新版本防护的突破口                        |
| `secret`                         | 秘密                  | 字面即敏感，常指向密钥/密码相关配置，信息泄露排查重点关键词                               |
| `key` / `keys`                   | 密钥                  | 同上，硬编码密钥泄露会直接影响加密/签名机制的安全性（参照前端加密笔记）                         |
| `token`                          | 令牌                  | 会话/身份凭证相关，若能在前端代码/响应中意外看到硬编码 Token，等同于直接拿到身份凭证               |
| `session`                        | 会话                  | 对应 Session 劫持/固定等一整类攻击，是身份验证审计的核心关键词                         |

## 二、渗透相关代码函数常用英文单词（构成函数名的核心词根）

> 很多函数名是"动词+名词"的组合，认识这些词根后，看到陌生函数名也能猜出大概用途。

| 英文词根                        | 中文         | 常见函数示例                                            | 安全意义（看到就该想到什么）                                   |
| --------------------------- | ---------- | ------------------------------------------------- | ------------------------------------------------ |
| `eval` (evaluate)           | 求值/执行      | `eval()`                                          | 把字符串当代码执行，**代码执行类漏洞的头号关键词**，参数若可控直接 RCE          |
| `exec` (execute)            | 执行         | `exec()`、`shell_exec()`                           | 执行系统命令，看到就该联想"命令注入"，检查参数拼接是否可控                   |
| `assert`                    | 断言（判断真假）   | `assert()`                                        | 低版本 PHP 中等效 `eval()`，容易被忽视的代码执行入口                |
| `include`                   | 包含         | `include()`、`require()`                           | 路径若可控 → 本地/远程文件包含（LFI/RFI），可能进一步升级为 RCE          |
| `require`                   | 需要/引入      | `require()`                                       | 同上，区别只是出错后是否终止脚本                                 |
| `read`                      | 读取         | `fread()`、`readfile()`、`readdir()`                | 路径可控时对应"任意文件读取/目录遍历"                             |
| `write`                     | 写入         | `fwrite()`、`document.write()`                     | 后端写文件要查"任意文件写入"；前端 `document.write()` 要查 DOM-XSS |
| `open`                      | 打开         | `fopen()`、`opendir()`                             | 打开的目标路径若可控，同样是文件操作类漏洞的切入点                        |
| `close`                     | 关闭         | `fclose()`                                        | 安全意义不大，纯资源释放操作                                   |
| `delete`                    | 删除         | `unlink()`                                        | 路径可控 → "任意文件删除"，可致拒绝服务或破坏关键文件                    |
| `move`                      | 移动         | `move_uploaded_file()`                            | 文件上传链路的最后一步，审计重点看目标路径和文件名是否可控                    |
| `copy`                      | 复制         | `copy()`                                          | 与 move 类似，复制目标路径可控时同样有路径穿越风险                     |
| `scan`                      | 扫描/遍历      | `scandir()`                                       | 配合用户可控路径 → 目录遍历/敏感文件列举                           |
| `filter`                    | 过滤         | `filter_var()`、`array_filter()`                   | **防御类函数**，审计时反而要看过滤规则是否足够严格、是否可绕过                |
| `validate`                  | 验证         | `FILTER_VALIDATE_EMAIL`                           | 同属防御类，关注校验逻辑本身是否存在逻辑漏洞（如正则写错）                    |
| `sanitize`                  | 净化/清洗      | `FILTER_SANITIZE_STRING`                          | 防御类函数，常见于 XSS/注入防护，但本身可能过滤不全                     |
| `escape`                    | 转义         | `escapeshellcmd()`、`htmlspecialchars` 的"escape"概念 | 防御类函数，但使用位置不对或遗漏参数仍可被绕过，命令注入/XSS 审计必查            |
| `strip`                     | 剥离/去除      | `strip_tags()`                                    | XSS 防护手段，但对畸形/嵌套标签等特殊构造可能存在绕过                    |
| `parse`                     | 解析         | `JSON.parse()`、`cookie-parser`                    | 解析不可信数据时，结果类型/内容未校验可能引发后续逻辑漏洞                    |
| `serialize` / `unserialize` | 序列化 / 反序列化 | `unserialize()`                                   | **反序列化漏洞**核心关键词，传入可控数据可能触发对象注入、RCE               |
| `encode` / `decode`         | 编码 / 解码    | `base64_encode()`                                 | 编码≠加密，看到 encode/decode 要留意是否被误当作安全防护手段使用         |
| `encrypt` / `decrypt`       | 加密 / 解密    | `CryptoJS.AES.encrypt()`                          | 前端加密审计核心词，需关注密钥/IV 是否硬编码在前端代码中                   |
| `hash`                      | 哈希         | `md5()`、`hash_equals()`                           | 涉及弱哈希比较（`==` 弱类型 0e 魔术哈希）等经典绕过点                  |
| `compare`                   | 比较         | `strcmp()`                                        | 弱类型比较漏洞关键词，传参类型异常可能导致比较函数返回异常结果                  |
| `search`                    | 查找         | `array_search()`                                  | 默认松散比较，白名单校验可能被类型混淆绕过                            |
| `replace`                   | 替换         | `preg_replace()`、`str_replace()`                  | `preg_replace` 配合 `/e` 修饰符历史上可致代码执行              |
| `match`                     | 匹配         | `preg_match()`                                    | 正则匹配常用于校验，关注正则本身是否写得不严谨（如忘加 `^$`）                |
| `redirect`                  | 重定向        | `window.location`、`header("Location:...")`        | 目标地址可控 → 开放重定向（Open Redirect），可配合钓鱼/OAuth 漏洞利用   |
| `connect`                   | 连接         | 数据库连接相关函数                                         | 连接串若硬编码账号密码，属于敏感信息泄露排查点                          |
| `query`                     | 查询         | SQL 查询相关函数                                        | **SQL 注入**核心关键词，参数是否拼接进查询语句是审计第一步                |
| `fetch`                     | 获取/抓取      | `fetch()` API                                     | 前端发起请求的核心函数，审计请求目标地址/参数构造逻辑                      |
| `register`                  | 注册         | `register_shutdown_function()`                    | 回调参数若可控，等同于自定义脚本结束时执行的代码可被攻击者指定                  |
| `handler`                   | 处理器        | `set_error_handler()`                             | 同上，事件钩子类函数，关注注册的处理函数名是否可控                        |
| `callback`                  | 回调         | 回调函数通用叫法                                          | 回调函数名若可控，等同于让攻击者决定调用哪个函数（见此前讲解）                  |
| `prototype`                 | 原型         | 原型链污染相关                                           | Node.js/JS 特有高危漏洞关键词，关注对象合并/深拷贝逻辑                |
| `upload`                    | 上传         | `move_uploaded_file()`                            | 对应"任意文件上传"全链路审计，是实战中最常见的 Getshell 路径之一           |
| `download`                  | 下载         | `readfile()` 配合下载响应头                              | 对应"任意文件下载"，文件名参数可控时测试路径穿越                        |
| `spawn`                     | 创建/生成（进程）  | `spawnSync()`                                     | Node.js 命令执行关键函数，参数可控即命令注入                       |
| `shell`                     | 命令行/系统壳层   | `shell_exec()`                                    | 看到 shell 相关词直接联想"命令执行"，是审计中最高优先级关键词之一            |

## 三、常见攻击术语英文单词

| 英文                        | 中文          | 说明                                                                                |
| ------------------------- | ----------- | --------------------------------------------------------------------------------- |
| `injection`               | 注入          | SQL Injection（SQL 注入）、Command Injection（命令注入）                                     |
| `traversal`               | 穿越/遍历       | Path/Directory Traversal（路径穿越）                                                    |
| `inclusion`               | 包含          | LFI（Local File Inclusion，本地文件包含）、RFI（Remote File Inclusion，远程文件包含）                |
| `execution`               | 执行          | RCE（Remote Code Execution，远程代码执行）                                                 |
| `bypass`                  | 绕过          | 权限绕过、过滤绕过                                                                         |
| `hijacking`               | 劫持          | Session Hijacking（会话劫持）、Click Hijacking（点击劫持）                                     |
| `fixation`                | 固定          | Session Fixation（会话固定）                                                            |
| `spoofing`                | 欺骗/伪造       | IP Spoofing（IP 欺骗）                                                                |
| `forgery`                 | 伪造          | CSRF（Cross-Site Request Forgery，跨站请求伪造）、SSRF（Server-Side Request Forgery，服务端请求伪造） |
| `enumeration`             | 枚举          | 用户名枚举、目录枚举                                                                        |
| `fuzzing`                 | 模糊测试        | 批量输入畸形/随机数据探测异常                                                                   |
| `brute force`             | 暴力破解        | 简称"爆破"                                                                            |
| `payload`                 | 攻击载荷        | 实际发送用于触发漏洞的恶意数据                                                                   |
| `exploit`                 | 漏洞利用（工具/过程） |                                                                                   |
| `vulnerability`           | 漏洞          | 简称 vuln                                                                           |
| `backdoor`                | 后门          |                                                                                   |
| `webshell`                | 网站木马        | 上传到服务器的恶意脚本文件                                                                     |
| `privilege escalation`    | 权限提升        | 简称提权                                                                              |
| `pollution`               | 污染          | Prototype Pollution（原型链污染）                                                        |
| `poisoning`               | 投毒          | Log Poisoning（日志投毒）、Cache Poisoning（缓存投毒）                                         |
| `disclosure`              | 泄露          | Information Disclosure（信息泄露）                                                      |
| `leakage`                 | 泄露          | 同上，另一种常见表达                                                                        |
| `tampering`               | 篡改          |                                                                                   |
| `manipulation`            | 操纵          | Cookie Manipulation（Cookie 操纵）                                                    |
| `redirection`             | 重定向         | Open Redirection（开放重定向）                                                           |
| `deserialization`         | 反序列化        | 反序列化漏洞                                                                            |
| `obfuscation`             | 混淆          | 代码混淆                                                                              |
| `reconnaissance`          | 侦察          | 简称 recon，即信息收集阶段                                                                  |
| `footprinting`            | 踩点          | 信息收集的另一种说法                                                                        |
| `fingerprinting`          | 指纹识别        | 识别目标技术栈/版本                                                                        |
| `pivoting`                | 跳板/横向渗透     | 以已攻陷主机为跳板攻击内网其他机器                                                                 |
| `lateral movement`        | 横向移动        | 内网渗透中从一台机器扩展到另一台                                                                  |
| `whitelist` / `blacklist` | 白名单 / 黑名单   |                                                                                   |
| `sanitization`            | 净化处理        | 对输入做安全处理                                                                          |
| `race condition`          | 竞态条件        | 并发场景下的逻辑漏洞                                                                        |
| `denial of service`       | 拒绝服务        | 简称 DoS                                                                            |

## 五、记忆建议

1. 不要孤立背单词，结合你已有的笔记去"组词"：比如看到 `local file inclusion`，直接联想到你《PHP文件操作安全笔记》里讲的 LFI 具体原理，词汇和知识点绑在一起记，效率更高。
2. 第二部分"代码函数词根"按"动词原形"记，再去反推具体函数——比如记住 `escape = 转义` 这一个词根，`escapeshellcmd`、`escapeshellarg`、`htmlspecialchars`（本质也是一种 escape）就能一并理解，而不是死记三个孤立的函数名。
3. 可以把这份表格拆到之前的《安全核心函数间隔重复复习表》里一起复习，按相同的间隔节奏（今天→2天→4天→7天→15天→30天）滚动巩固。
