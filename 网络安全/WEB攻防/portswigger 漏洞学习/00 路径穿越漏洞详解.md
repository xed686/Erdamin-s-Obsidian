# 路径穿越(Path Traversal)漏洞详解

## 1. 一个比喻先理解

想象一个图书馆管理员,规则是:"读者说一个书名,你就去 **3 楼 A 区书架** 拿这本书给他。"

正常读者说"《红楼梦》",管理员去 3 楼 A 区拿书。

但如果读者说"**先下到 1 楼,再去档案室,拿机密档案**",而管理员没有检查就照做了,读者就拿到了本不该看的东西。

路径穿越就是这样:**程序本来只想让你读某个文件夹里的文件,但你用特殊写法"跳出"了这个文件夹。**

---

## 2. 正常情况下程序怎么工作

网页里有一张商品图:

```html
<img src="/loadImage?filename=218.png">
```

服务器后台的逻辑大致是:

```
基础目录 = /var/www/images/
实际读取 = 基础目录 + 用户传来的 filename
         = /var/www/images/218.png
```

关键点在于 **`filename` 是用户可控的**,而服务器只是简单地把它拼在后面,没有做任何检查。

---

## 3. 攻击的核心:`../` 是什么

在文件系统里,`../` 表示**回到上一级目录**。

假设当前处于 `/var/www/images/`:

| 写法 | 含义 | 所在位置 |
|---|---|---|
| `../` | 上一级 | `/var/www/` |
| `../../` | 上两级 | `/var/` |
| `../../../` | 上三级 | `/`(根目录) |

---

## 4. 攻击一步步发生

攻击者把 filename 参数改成:

```
../../../etc/passwd
```

服务器照常拼接:

```
/var/www/images/ + ../../../etc/passwd
= /var/www/images/../../../etc/passwd
```

操作系统从左到右解析这个路径:

1. 进入 `/var/www/images/`
2. `../` → 退到 `/var/www/`
3. `../` → 退到 `/var/`
4. `../` → 退到 `/`
5. 再进入 `etc/passwd` → 最终读取的文件是 **`/etc/passwd`**

**结果:** 本来只能读图片文件夹,现在却读到了系统用户文件。

> **补充:** `../` 写多了也没关系。一旦到达根目录 `/`,再往上还是根目录,不会报错。所以实战中攻击者常常多写几个 `../`,不用精确数层数。

---

## 5. Windows 系统的区别

Windows 的路径分隔符是 `\`,但 `/` 和 `\` 都有效,所以 `../` 和 `..\` 都能用来穿越目录。目标文件也换成 Windows 系统的,例如:

```
https://insecure-website.com/loadImage?filename=..\..\..\windows\win.ini
```

---

## 6. 为什么它是一个漏洞

根本原因只有一个:

> **程序信任了用户输入,没有限制最终读取的路径必须在指定目录范围内。**

危害取决于攻击者能读到什么内容:

- 应用源代码和数据
- 数据库配置文件、后端凭证
- 系统账户文件、SSH 密钥等敏感文件

在某些情况下,攻击者甚至能够**写入**服务器上的任意文件,从而修改应用数据或行为,最终完全控制服务器。

---

## 7. 渗透测试视角:怎么找、怎么测

**找入口** —— 留意像文件名或路径的参数,例如:

- `filename=`
- `file=`
- `path=`
- `page=`
- `template=`
- `download?name=`

**测试方法** —— 把参数值换成:

```
../../../etc/passwd
```

观察响应里是否出现 passwd 文件的内容。

**遇到过滤时的常见绕过思路** —— 开发者常做简单防御(比如直接删除 `../`),于是出现各种绕过写法:

- URL 编码:`%2e%2e%2f`
- 双重编码:`%252e%252e%252f`
- 嵌套写法:`....//`(过滤器删掉中间的 `../` 后,会拼出新的 `../`)
- 直接使用绝对路径:`/etc/passwd`

> PortSwigger Web Security Academy 的 Path Traversal 系列靶场正好按这些绕过方式分关卡,适合边学边练。

---

## 8. 正确的防御方式(理解漏洞的另一面)

- **最佳做法:** 不让用户直接传文件名,改用 ID 映射(如 `id=3` 对应服务器上固定的文件)
- **若必须使用文件名:** 先对路径做**规范化**处理(解析掉所有 `../`),再检查最终路径是否仍然以允许的基础目录开头,不是则拒绝请求

---

## 一句话总结

> 用户输入被直接拼进文件路径,通过 `../` 往上退出目录限制,就能跳出本该限制的文件夹,读取(甚至写入)服务器上不该访问的文件。
