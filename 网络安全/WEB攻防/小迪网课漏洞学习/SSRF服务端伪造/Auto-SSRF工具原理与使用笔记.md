## 一、它到底自动化了什么（和手工对照）

挖盲打 SSRF 时，你手工要做这一串动作。Auto-SSRF 把其中**机械重复**的部分全接管了：

| 步骤 | 手工怎么做 | Auto-SSRF 怎么做 | 谁来做 |
|---|---|---|---|
| 1. 找可疑参数 | 在 history 里一条条翻，看哪个参数名像 `url`、或值是个链接 | 自动扫每条流量的参数，命中规则就挑出来 | ✅ 工具 |
| 2. 生成探测地址 | 去 Collaborator 点"复制"，拿一个 `xxx.oastify.com` | 每次检测自动生成一个**专属 payload** | ✅ 工具 |
| 3. 替换参数值 | 手动把参数值改成 `http://xxx.oastify.com/` | 自动替换，且能处理 **URL 参数 / JSON / XML / 表单 / Cookie** | ✅ 工具 |
| 4. 重新发包 | 复制到 Repeater，手动 Send | 自动重发改造后的请求 | ✅ 工具 |
| 5. 盯回连 | 回 Collaborator 反复点"轮询"，看有没有记录 | 自动轮询，并把**回连和原请求一一对应** | ✅ 工具 |
| 6. 去重 | 全靠记忆，容易重复测同一个点 | 用缓存按"路径+参数名"去重，测过的不再测 | ✅ 工具 |
| 7. **确认能否利用** | 试内网访问、读元数据、换协议、绕过滤 | **不做** | ❌ 你自己 |
| 8. **判定危害/写报告** | 结合业务判严重程度 | **不做** | ❌ 你自己 |

一句话：**第 1~6 步（又烦又重复的体力活）工具全包了，第 7~8 步（真正定性的脑力活）留给你。** 它是"初筛器"，不是"确认器"。

## 二、原理：拆成四步看

### 第一步：挂钩流量（它从哪拿请求）

插件在 Burp 里注册了两个监听点，对应配置里的三个开关：

- **被动扫描（ScanCheck）**：接 Burp 自带的被动扫描器，Burp 被动审计到的流量都会流过来。
  - ⚠️ 所以插件整体的"开关"其实取决于 **Burp 的被动扫描是否开着**。被动扫描关了，这条路就不触发。
- **Proxy / Repeater（HttpHandler）**：监听响应，判断流量来源：
  - 来自 Proxy 且你开了"扫描 Proxy" → 处理
  - 来自 Repeater 且你开了"扫描 Repeater" → 处理

> 为什么要分来源？因为 Proxy 流量量大（你浏览产生的一切），Repeater 是你手工发的精准流量。分开开关，让你能控制"要不要对海量 Proxy 流量都自动打一遍"。

### 第二步：过滤 + 去重（它挑哪些参数）

不是每条流量都测，否则噪声爆炸。它的判定规则（源码里写死的）很简单：

> **一个参数"可疑"的条件：参数名里含 `url`，或者参数值里含 `http`/`https`。**

命中的参数来自三类位置：**URL query 参数、请求体参数（含 JSON/XML/表单）、Cookie**。

然后做**去重**：把"请求路径 + 命中的参数名"拼成字符串算 MD5，丢进一个最多 5 万条的缓存。

- 这个请求的"路径+参数名组合"没见过 → 测，并记进缓存
- 见过 → 跳过

> 为什么这样去重？因为同一个接口你可能浏览时触发几十次，参数值每次不同但"点"是同一个。按"路径+参数名"去重，保证**同一个注入点只测一次**，既省 Collaborator 资源又不刷屏。重启 Burp 缓存会清空，所以插件提供了"缓存持久化"把它存文件。

### 第三步：注入 + 重发（它怎么打）

对每个可疑参数，把它的值替换成：

```
http://<本次专属的 Collaborator 地址>/<6位随机字符串>
```

- **专属地址**：每次检测生成一个独立 payload，这样回连回来时能精确对应到是哪条请求、哪个参数触发的。
- **6 位随机串**：避免路径相同导致的误判/缓存混淆。
- **按类型重建请求**：参数在 JSON 里就改 JSON、在 XML 里就改 XML、在表单里就改表单——不会把结构搞坏。

改好后，自动把这个请求发出去。

### 第四步：收口（怎么算命中）

发完请求后，它**轮询 Collaborator**（最多 10 次，中间有秒级间隔），拿这个专属 payload 的回连记录：

- 收到 **HTTP 类型**的回连 → 判定**疑似 SSRF**，状态标 `SUCCESS`，进漏洞表。
- 只收到 DNS、或啥都没收到 → 判 `FAILED`。

> ⚠️ **关键细节**：它只认 **HTTP 回连**，不认纯 DNS。好处是误报极低（对方真的发了 HTTP 请求才报）；代价是**有些盲 SSRF 只做 DNS 解析、不发 HTTP**，这类它会漏。这点和 Collaborator Everywhere（DNS 也标）形成互补。

## 三、界面怎么用

插件顶部 `Auto-SSRF` 标签，几个核心配置（都在源码里对得上）：

| 配置项 | 作用 | 建议 |
|---|---|---|
| **被动扫描** | 接 Burp 被动扫描器的流量 | 想全自动就开；注意它依赖 Burp 被动扫描本身开着 |
| **扫描 Proxy** | 对所有经过代理的流量自动打 | **慎开**，量大、会对你浏览的所有站点发包 |
| **扫描 Repeater** | 对你在 Repeater 发的流量打 | 推荐开，精准、可控 |
| **线程池大小** | 并发发包/轮询的数量 | 默认即可，网络差就调小 |
| **缓存持久化** | 把去重缓存存文件，重启不丢 | 长期测同目标可开 |
| **保存配置** | 把配置存文件，重启自动恢复 | 配好一次就存 |

**两个结果区**：

- **Dashboard（仪表盘/任务表）**：所有被检测的请求 + 状态（CHECKING/SUCCESS/FAILED/ERROR），看它在忙什么。
- **漏洞表**：命中（SUCCESS）的请求集中在这，这是你要重点看的地方。

**推荐用法**：
- 平时把**扫描 Proxy 关掉**，靠 **Repeater** 精准测——你怀疑某个点时丢进 Repeater 发一下，它自动帮你盲打。
- 要大面积扫时再开 Proxy，但务必先配好 Scope、只在授权目标上开。

## 四、它的盲区（这些仍要你手工）

工具的过滤规则决定了它**只盯"名字含 url 或值是 URL"的参数**，所以以下点它看不到，得你手工补：

1. **参数名不含 url、值也不是完整 URL** 的点。比如参数只传一个**主机名/IP**（`host=10.0.0.1`）、或 URL 被 **base64/编码**过——它判不出来。
2. **请求头里的 SSRF**（如 `Referer`、`X-Forwarded-For`）——它只看参数，不碰任意头。→ 这正是 **Collaborator Everywhere** 补位的地方。
3. **只触发 DNS、不发 HTTP 的盲 SSRF**——它不认 DNS 回连。
4. **确认利用**：命中后能不能访问内网、读云元数据（`169.254.169.254`）、用 `file://`/`gopher://`、绕 SSRF 过滤——全靠你手工验证，工具只告诉你"这里服务端确实会发请求"。

## 五、三件套怎么配合（SSRF 视角）

挂代理浏览授权目标，三个插件各司其职：

- **HaE** → 标出"参数名像 url""参数值是 URL""危险路径"的报文（你刚加的第 6、7 节规则），帮你**肉眼锁定可疑点**。
- **Auto-SSRF** → 对参数类 SSRF 点**自动盲打 + 回连确认**。
- **Collaborator Everywhere** → 对**请求头类** SSRF 点注入探测，补 Auto-SSRF 的盲区。

命中后统一回到手工：验证能否打到内网/元数据，判危害，再决定是否提交。

---

## 六、合规提醒

Auto-SSRF 会**真实地向目标重发请求**。开着"扫描 Proxy"时，你浏览过的所有站点都可能被自动打一遍。**只在你有授权的目标上开**，平时用 Scope 限定范围、或只走 Repeater，避免对无关站点发包。
