# SQL 盲注原理笔记：布尔 / 报错 / 延时

> **与前置笔记的关系**：上一篇《HTTP请求头注入面与增删改查注入思路笔记》结尾讲到，INSERT/UPDATE/DELETE 这类不产生结果集的语句，核心替代手法是"报错注入"和"布尔/时间盲注"，但当时只是提了个名字、没有展开具体怎么判断、怎么选。今天这篇就是把这三类盲注手法**彻底拆开，逐个函数、逐行 payload 翻译成人话**，让你看到任何一条盲注语句都能立刻反应出"这句话到底在问数据库什么问题"。

---

## 一、什么是盲注，为什么需要它

**人话翻译**：盲注的"盲"，说的不是你瞎打，而是**数据库查到的数据，不会被页面直接显示出来给你看**。前面几篇笔记讲的联合查询注入（`union select`），前提是页面会"回显"数据——你注入的内容能直接出现在页面上。但现实中大量场景根本不回显任何数据（比如一个"登录成功/登录失败"的提示，背后可能查了一大堆用户数据，但页面只给你两种结果：成功或失败）。

**这种情况下你怎么从数据库里"偷"数据出来**：既然看不到数据本身，那就想办法让数据库做一些**只有"是"或"否"两种结果**的事情，然后你通过观察这两种结果的差异（页面内容不同、响应时间不同、有没有报错），一点一点**猜**出真实数据——这就是"盲注"这个名字的由来，整个过程就像蒙着眼睛摸索。

---

## 二、三种盲注类型总览

| 类型       | 判断依据（人话）          | 需要什么条件                                  | 常用函数                                                |
| -------- | ----------------- | --------------------------------------- | --------------------------------------------------- |
| **布尔盲注** | "页面内容/状态有没有变化"    | 页面对"真"和"假"两种结果表现不同（比如有数据/无数据，文案 A/文案 B） | `regexp`、`like`、`ascii`/`ord`、`left`、`mid`/`substr` |
| **时间盲注** | "这次响应是不是比平时慢"     | 什么差异都看不出来时的最后手段，只要数据库能正常执行查询就一定能用       | `if`、`sleep`                                        |
| **报错注入** | "报错信息里有没有包含我要的数据" | 应用把数据库的报错堆栈直接显示在了页面上                    | `floor`、`updatexml`、`extractvalue`                  |

**怎么选用哪一种（人话版判断流程）**：

1. 先试试页面会不会把数据库报错信息显示出来——**显示就用报错注入**，因为这是效率最高的方式（一次报错就能直接把数据"打印"出来，不用一个字符一个字符猜）。
2. 如果不报错，但页面在"条件为真/假"时表现不一样（比如有结果 vs 没结果）——**用布尔盲注**。
3. 如果页面对真假完全没有任何肉眼可见的差异——**只能用时间盲注**，这是"什么条件都不满足"时的兜底方案，所以笔记里写"基于延时：都不需要"，意思是它不挑场景，只要能执行 SQL 就一定能用，但效率也最低（每猜一次都要真的等上几秒）。

## 三、核心函数人话翻译

### 3.1 字符串匹配类（用于布尔盲注）

| 函数/语法                   | 人话翻译                | 示例                      | 示例人话翻译                                                             |
| ----------------------- | ------------------- | ----------------------- | ------------------------------------------------------------------ |
| `like 'ro%'`            | "这个字符串是不是以 ro 开头的"  | `like 'ro%'`            | 判断某个值是不是"ro"或"ro后面还跟着别的字"，相当于问"前两个字是不是 r 和 o"                      |
| `regexp '^xiaodi[a-z]'` | "这个字符串是不是严格按这个格式长的" | `regexp '^xiaodi[a-z]'` | 问"这个值是不是以 xiaodi 开头，后面紧跟着一个小写字母"，`regexp` 比 `like` 能表达更精确、更复杂的格式要求 |

### 3.2 字符截取与判断类（布尔盲注的主力）

| 函数                             | 人话翻译                                        | 示例                            | 示例人话翻译                                                                                                     |
| ------------------------------ | ------------------------------------------- | ----------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `left(a,b)`                    | "把字符串 a 从左边数，截前 b 个字"                       | `left(database(),1)`          | "当前数据库名字的第 1 个字是什么"                                                                                        |
| `mid(a,b,c)` / `substr(a,b,c)` | "从字符串 a 的第 b 个位置开始，往后数 c 个字"                | `substr(database(),2,1)`      | "当前数据库名字，从第 2 个字开始，取 1 个字"，等于问"第 2 个字是什么"                                                                  |
| `length(a)`                    | "字符串 a 一共有多少个字"                             | `length(database())=7`        | "当前数据库名字的长度，是不是正好 7 个字"                                                                                    |
| `ord(x)` / `ascii(x)`          | "字符 x 对应的 ASCII 编码数字是多少"（两个函数作用完全一样，只是叫法不同） | `ord(left(database(),1))=112` | "数据库名的第 1 个字，它的 ASCII 编码是不是 112"（查表可知 112 就是小写字母 `p`，所以这句话本质上是在问"数据库名是不是以 p 开头"，只是用编码数字而不是直接写字母来比较，原因见下一节） |

**为什么要绕个圈子用 `ord()`/`ascii()` 转成数字比较，而不是直接写 `left(database(),1)='p'` 这种字母比较**：两种写法其实都能用，笔记里两种都列出来了（`left(database(),1)='p'` 和 `ord(left(database(),1))=112` 是等价的两种问法）。用数字比较的好处是：**写自动化脚本时，数字比较（大于、小于、等于）天然支持"二分查找"**——比如先问"这个字的编码是不是大于 100"，再根据回答不断缩小范围，猜一个字符最多只需要 7-8 次（0-255 范围二分），而直接按字母一个一个试最多要试 26 次，效率天差地别。人工测试时直接比字母更直观，但理解"为什么工具喜欢用 ASCII 数字"这一点很重要。

### 3.3 条件与延时类（时间盲注的主力）

| 函数           | 人话翻译                   | 示例           | 示例人话翻译                                                                      |
| ------------ | ---------------------- | ------------ | --------------------------------------------------------------------------- |
| `if(条件,a,b)` | "如果条件成立就返回 a，不成立就返回 b" | `if(条件,5,0)` | "条件对不对？对的话给我 5，不对给我 0"——这个函数本身不会制造延时，它的作用是"做条件判断"，真正制造延时的是配合它一起用的 `sleep()` |
| `sleep(n)`   | "让数据库这条语句卡住、晾 n 秒再继续"  | `sleep(5)`   | "故意拖延 5 秒钟才把结果返回给你"                                                         |

**两者为什么总是一起出现**：单独一个 `sleep(5)` 只会让每次请求都固定变慢 5 秒，没有任何判断意义；只有把它塞进 `if()` 的"条件成立才执行"的位置，才能做到"**只有我猜的条件是对的，页面才会变慢；猜错了就正常速度返回**"——这个"是否变慢"的差异，就是时间盲注用来传递"真/假"信息的唯一渠道。

### 3.4 报错类（报错注入的主力）

| 函数                                           | 人话翻译                                                                                                                                              |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `updatexml(1, concat(0x7e, (子查询), 0x7e), 1)` | "我假装要往一段 XML 里插入内容，但故意在内容里拼了一段根本不符合 XML 格式的东西（因为前面多塞了一个 `0x7e`，也就是字符 `~`），这会导致这个函数直接报错，而报错信息里会**原样把你拼进去的内容显示出来**——所以我们偷偷把想要的数据塞在这段"会被迫显示在报错里"的位置" |
| `extractvalue(1, concat(0x5c, (子查询)))`       | 原理和 `updatexml` 一模一样，**也是故意制造一个格式错误触发报错，报错信息里带出数据**，只是换了一个函数、换了一个开头的"干扰字符"（`0x5c` 是反斜杠 `\`），两个函数在实战中可以互相替代使用                                      |

**这两个函数有一个共同的隐藏限制**：它们能通过报错带出来的内容长度是**有限的**（通常是 32 个字符左右），如果你要的数据（比如一长串表名拼接结果）超过这个长度，需要配合 `substr()`/`left()` 分段多次获取，这是实战中容易踩的坑。

## 四、三类盲注代表 payload 逐行人话翻译

### 4.1 延时类

```sql
and sleep(1);
```

**人话**："不管前面查询结果是真是假，我都强制让这条语句卡 1 秒"——这一句通常不是用来猜数据的，而是**最初用来确认"这个参数到底存不存在注入"的探测手段**：如果响应真的慢了 1 秒，说明你写的 SQL 代码被数据库真的执行了，而不是被当成普通文本处理掉了。

```sql
and if(1>2,sleep(1),0);
```

**人话**："如果 1 大于 2（这当然是假的），就卡 1 秒，否则立刻返回"——这句话的设计目的是**制造一个必定为假的对照组**：正常情况下这句话执行后不应该有任何延迟，用来确认"延迟是不是真的由条件触发的，而不是网络波动等其他原因造成的"。

```sql
and if(1<2,sleep(1),0);
```

**人话**："如果 1 小于 2（这显然是真的），就卡 1 秒"——这是上一句的**对照实验**：如果这句话执行后真的延迟了 1 秒，而上一句（条件为假）没有延迟，两相对比，就能确认"这个参数存在注入，而且数据库会按我写的条件真假去执行不同的逻辑"，这也是判断"这里能不能用时间盲注"的标准测试组合。

### 4.2 布尔类

```sql
and length(database())=7;
```

**人话**："当前这个数据库的名字，是不是正好 7 个字？"——通常是摸清数据库名之前的第一步，先确认长度，后面才能按长度一位一位猜字符。

```sql
and left(database(),1)='p';
```

**人话**："数据库名字的第 1 个字，是不是字母 p？"

```sql
and left(database(),2)='pi';
```

**人话**："数据库名字的前 2 个字，是不是 pi？"——和上一句是同一个猜测过程的延续，一步步把已经猜对的部分往后拼接，直到拼出完整名字。

```sql
and substr(database(),1,1)='p';
```

**人话**：和 `left(database(),1)='p'` 问的是**完全一样的问题**（从第 1 位开始取 1 个字，是不是 p），只是换了一个函数名字，`substr` 和 `left` 在这种场景下可以互相替代。

```sql
and substr(database(),2,1)='i';
```

**人话**："数据库名字从第 2 个位置开始，取 1 个字，是不是字母 i？"——配合上一句，一次锁定一个字符的位置继续往后猜。

```sql
and ord(left(database(),1))=112;
```

**人话**："数据库名字的第 1 个字，它的 ASCII 编码是不是 112？"——和前面讲过的一样，112 对应的就是小写字母 `p`，这句话和 `left(database(),1)='p'` 本质是同一个问题的两种问法。

### 4.3 报错类

```sql
and updatexml(1,concat(0x7e,(SELECT version()),0x7e),1)
```

**人话**："故意构造一个格式错误的 XML 操作，但在出错之前，先把数据库版本号（`SELECT version()`）夹在两个 `~` 符号中间塞进去——反正这个操作一定会报错，干脆把我想要的数据顺路塞进这次报错里一起显示出来。"

```sql
and extractvalue(1, concat(0x5c, (select table_name from information_schema.tables limit 1)));
```

**人话**："同样是故意制造报错，这次塞进报错信息里的内容是 information_schema.tables 这张系统表里的第一条表名记录"——`limit 1` 的作用是"只要第一条"，因为报错注入一次只能带出一点内容，必须配合 `limit` 一条一条分批获取多行数据（这一点和前面几篇笔记里 `group_concat()` 能一次拼出多行结果的玩法不同，报错注入通常做不到"一次性拼接多行"，因为报错信息长度本身就很有限）。

## 五、演示案例逐句人话翻译

> 这三组示例是在模拟"遇到一个新的注入点，第一时间该怎么快速判断它属于哪种场景"，对应本文第二节"怎么选用哪一种"的判断流程。

### 案例一：SELECT 没报错，但 INSERT 有报错

```sql
x' or updatexml(1,concat(0x7e,(version())),0) or '#
```

**人话**：先用单引号 `x'` 把原本的字符串闭合掉，然后用 `or` 接上一个"一定会报错"的表达式（因为 `updatexml` 的第二个参数故意写得不完整，缺了闭合的 `~`，格式不对），最后再用 `or '` 和 `#` 把原语句剩下的部分处理干净。**这句话的实际用途是探测**：丢进 SELECT 类型的参数里页面正常（说明 SELECT 场景这里没有把报错显示出来，或者这个点本身更适合用别的方式测），丢进 INSERT 类型的参数里页面报错了（说明 INSERT 这条路**适合用报错注入**，因为报错信息被暴露出来了）——通过同一句 payload 在不同功能点的不同反应，判断该用哪种手法。

### 案例二：SELECT 有输出，但 INSERT 没输出

```sql
x' or length(database())=15#
```

**人话**："判断当前数据库名字的长度是不是 15"。丢进 SELECT 类型的功能点，页面数据有变化（比如多显示了一条匹配结果）——说明这里**适合用布尔盲注**，能通过页面内容变化判断真假；丢进 INSERT 类型的功能点，页面完全没反应——说明 INSERT 这条路布尔盲注这里走不通（可能是因为 INSERT 操作本身执行后压根不会在页面上展示判断依据），需要换别的信号来源（比如本例对应的下一条，换成延时判断）。

### 案例三：既不报错也没有任何输出变化

```sql
x' or if(1=1,sleep(5),0)#
x' or if((select database())='news_management',sleep(1),sleep(0))#'
```

**人话**：第一句是**探测语句**——"如果 1 等于 1（恒真），就卡 5 秒"，用来确认"这里到底能不能执行时间盲注"；如果确认能用，第二句就是**实际验证语句**——"如果当前数据库名字就是 news_management，卡 1 秒，否则不卡"，用一个**具体猜测**去验证，这是在"报错注入、布尔盲注都用不了"的情况下唯一能用的兜底手段，对应前面讲的"基于延时：都不需要"这句话的含义——它不挑剔页面有没有回显、会不会报错，只要数据库真的执行了你的条件判断就一定能观察到延时差异。

## 六、实际案例人话翻译

### 6.1 XHCMS —— INSERT 报错注入

```sql
' and updatexml(1,concat(0x7e,(SELECT version()),0x7e),1) and '
```

**人话**：先用单引号闭合掉原本 INSERT 语句里某个值的字符串，中间插入一个"故意触发报错、同时把数据库版本号塞进报错信息里"的表达式，最后再用一个单引号把原语句剩下的部分重新"接上"，保证整体语法依然说得通。能用这招的前提是：**XHCMS 这个应用在用户提交数据（走 INSERT 流程，比如注册、提交内容等功能）时，直接把数据库报错信息展示在了页面上**，这正好对应本文第二节判断流程的第一步——"先试试报不报错"，而这里命中了。

### 6.2 KKCMS —— DELETE 延时注入，完整猜测过程还原

```sql
or if(1=1,sleep(5),0)
```

**人话**：第一句永远是探测——"条件恒真就卡 5 秒"，用来确认 KKCMS 的删除功能这个参数位置确实存在注入，且这里属于"没报错、没回显，只能用延时"的情况。

```sql
or length(database())=5
```

**人话**："当前数据库名字是不是正好 5 个字"——注意这一句虽然原始笔记写的是布尔式的写法（没有配合 `sleep`），但在"没有任何回显变化"的前提下，**真正要让这句话有判断意义，需要配合 `if()+sleep()` 包一层**（也就是前面讲的"延时套娃判断"），单纯这样写在无回显场景下是看不出真假的，这里是在确认"长度为 5"这个猜测方向，实战中这一步应该和前一步一样，用 `if(length(database())=5,sleep(1),0)` 的完整形式去验证。

```sql
or if(ord(left(database(),1))=107,sleep(1),0)
```

**人话**："数据库名字第 1 个字的 ASCII 编码是不是 107？如果是就卡 1 秒。"查 ASCII 表可知 107 对应小写字母 `k`——**这正好对应"kkcms"这个应用自己的名字**，侧面说明这类 CMS 系统的数据库名经常直接用应用名本身（或者简写）来命名，这也是实战中一个很实用的"猜测捷径"：**先尝试猜数据库名是不是就是应用名本身**，往往能节省大量盲注尝试次数。

```sql
or if(ord(substr(database(),2,1))=107,sleep(1),0)
```

**人话**："数据库名字第 2 个位置的那个字，它的 ASCII 编码是不是也是 107（也就是字母 k）？"——沿着上一句的思路继续往后猜第 2 个字符，如果这一步也猜中了（第 2 个字也是 `k`），再结合第一步确认的"长度是 5"，猜测方向会进一步collapse 到"数据库名很可能是 `kkcms` 本身"这个结论上，后续只需要针对这个猜测做一次整体验证（`if(database()='kkcms',sleep(1),0)`）就能一次确认，而不需要再一个字符一个字符慢慢猜完剩下的 3 位。

## 七、总结：三类盲注 + 联合查询，拼成完整工具箱

结合上一篇《HTTP请求头注入面与增删改查注入思路笔记》的结论，现在你手上已经有了应对几乎所有场景的完整判断流程：

```
拿到一个疑似注入点
    ↓
① 它背后是 SELECT 还是 INSERT/UPDATE/DELETE？
    SELECT 且有回显 → 优先联合查询注入（union select）
    ↓（以下场景无法用 union，统一走盲注/报错注入）
② 页面会不会直接显示数据库报错信息？
    会 → 报错注入（updatexml / extractvalue，效率最高，一次就能带出数据）
    ↓
③ 页面对"条件真/假"有没有肉眼可见的差异（内容、状态）？
    有 → 布尔盲注（length / left / substr / ord 等，逐字符猜测）
    ↓
④ 以上都不满足？
    → 时间盲注（if + sleep，兜底方案，效率最低但适用面最广）
```

今天这篇笔记的核心价值，是让你看到任何一条盲注 payload，都能立刻在脑子里把它"翻译"成一句人话问句——这才是真正理解盲注的标志，而不是死记硬背 `updatexml`、`ord`、`substr` 这些函数名本身。
