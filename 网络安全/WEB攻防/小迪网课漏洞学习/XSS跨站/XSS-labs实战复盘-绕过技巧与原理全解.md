## 0. 贯穿全篇的核心思想(先建立总纲)

打完整个 xss-labs,最该带走的不是 20 个 payload,而是这一条**统一的思想**:

> **所有 XSS 过滤绕过,本质都是利用"过滤器看到的内容"和"浏览器最终解析/执行的内容"之间的不一致(认知差)。过滤器堵一个点,你找它没覆盖、但浏览器认可的另一个点,从缝里钻过去。**

每一关的过滤器,都有一个**它没考虑周全的盲区**。你的工作就是:
1. **先诊断**:把 payload 丢进去,看 DOM 里被过滤成了什么样(这一步暴露过滤规则)
2. **找盲区**:判断过滤器漏了什么(大小写?其他空白符?编码?调用方式?)
3. **对症绕过**:用那个盲区对应的技巧

**这套"诊断→找盲区→对症"的流程,比任何单个 payload 都重要。** 下面每一关,都是这个流程的一次实例。

## 1. 两个最底层的判断(贯穿所有关卡)

在讲具体技巧前,先立两个"判断轴",它们决定你用哪类打法:

### 判断轴一:我的输入落在"HTML 环境"还是"JS 环境"?(🔴 核心,最易混)

这是 level 17/18 血泪换来的认知。**同样是"闭合引号",两种环境的后续打法完全不同:**

| 环境 | 输入落在哪 | 闭合什么 | 闭合后怎么执行 JS |
|---|---|---|---|
| **HTML 环境** | `<input value="输入">`、标签属性里 | 闭合 `"` 或 `'`(属性引号) | **加事件属性** `onfocus=alert()`(HTML 里不能直接跑 JS,要靠事件) |
| **JS 环境** | `<script>var k='输入'</script>` | 闭合 `'`(JS 字符串引号) | **直接写 JS** `alert()`(已经在 JS 里了,直接执行) |

**致命误区(我踩过)**:在 HTML 环境里用 JS 环境的打法——比如 input 的 value 里,闭合引号后直接写 `alert(1)`,结果 `alert(1)` 变成了一个废的 HTML 属性,不执行。**HTML 里执行 JS 必须靠事件属性,不能裸写 alert。**

**怎么判断**:看 F12 源码,你的输入是在 `<标签 属性="这里">` 里(HTML 环境),还是在 `<script>` 标签内被引号包着(JS 环境)。

### 判断轴二:"没弹窗"不是终点,是诊断信息(🔴 核心)

每次 payload 没触发,**别急着换下一个,先去 F12 看它被过滤成了什么样**。过滤后的那个形态,暴露了过滤规则的全部信息:
- 变成 `&lt;` → 尖括号被实体化(打不了标签)
- 关键字没了 → 关键字被删/替换
- 空格变 `&nbsp;` → 分隔符被破坏
- `alert(1)` 变 `alert1` → 括号被吃

**看清"它把我改成了什么",对症的绕过方法自己就浮现了。** 这是老手和新手的分水岭。

## 2. 过滤绕过技巧全集(按"过滤器盲区"分类)

### 2.1 闭合逃逸(输入被困在属性/标签里)🔴

**场景**:输入落在 `<input value="这里">` 或某标签属性里,被引号/标签包着。
**技巧**:用 `">` 闭合标签逃出去,或用 `"`/`'` 闭合属性,再加事件。

```
" onfocus=alert(1) autofocus     ← 闭合 value 引号,加 onfocus 事件 + autofocus 自动触发
"><img src=x onerror=alert(1)>   ← 闭合标签,打新标签(尖括号没被过滤时)
```

> **触发细节(level 18 的坑)**:`onfocus` 需要元素"获得焦点"才触发。加 `autofocus` 让它自动获焦;若 autofocus 没生效(焦点被别处抢了),**手动点一下那个输入框**也能触发。或换 `onmouseover`(鼠标划过)/`onclick`(点击)这类不依赖 autofocus 的事件。

### 2.2 换执行入口(`<script>` 或事件被封)🔴

**场景**:`<script>` 被过滤,或某个事件被封。
**技巧**:JS 的执行入口不止一个,换一个过滤器没堵的。

```
<img src=x onerror=alert(1)>        ← 图片加载失败,自动触发 onerror(首选,自动)
<svg onload=alert(1)>               ← SVG 加载完,自动触发 onload(关键字冷门,自动)
<a href=javascript:alert(1)>x</a>   ← href 伪协议,点击触发(需点击)
<input onfocus=alert(1) autofocus>  ← 自动获焦触发
```

> **为什么 `<svg onload>` 和 `<img onerror>` 是主力**:它们**自动触发**(不需要用户操作),真实攻击里你没法要求受害者去点,所以自动触发的 payload 最有价值。`onclick`/`onfocus`(无autofocus)要用户操作,是备胎。
> **为什么 `<svg>` 比 `<img>` 更易绕**:大家过滤时盯着 `img`/`script`,容易漏 `svg`;且 svg 更短。

### 2.3 大小写绕过(正则没管大小写)🔴

**场景**:过滤器用正则匹配关键字,但只匹配了小写(没加忽略大小写标志)。
**技巧**:关键字大小写混写,HTML/JS 不区分大小写照样执行,但骗过只匹配小写的正则。

```
<sCript>alert(1)</sCript>
<img src=x OnErRoR=alert(1)>
```

### 2.4 双写绕过(关键字只删一次,没递归删)🔴

**场景**:过滤器把关键字删除(替换成空),但**只扫描删除一次**,不回头检查删完后剩下的字符会不会又拼成关键字。
**技巧**:把关键字拆开、中间夹一个完整关键字,删掉内层后外层自动合体。

```
<scrscriptipt>...   ← 过滤删掉中间的 script,剩下 scr+ipt 拼回 script
hrehreff            ← 删掉中间的 href,剩下 hre+f 拼回 href
oonnload            ← 删掉中间的 on,剩下 o+nload... (视实现)
```

> **原理**:`str_replace("script","",...)` 只扫一遍。`scrscriptipt` → 删中间 `script` → `scr`+`ipt` 相邻拼成 `script`,而过滤器已经扫完不回头了 → 绕过。防御正解:**循环删除直到不再变化**。

### 2.5 编码绕过(过滤器不解码,浏览器会解码)🔴 核心中的核心

**场景**:过滤器在"字符串层面"匹配关键字,而浏览器解析时会自动解码 HTML 实体。
**技巧**:把关键字用 HTML 实体编码(`&#xNN;`)写,过滤器看到一堆编码字符不认识而放行,浏览器解析时自动解码还原执行。

```
href=&#x6a;&#x61;&#x76;&#x61;&#x73;&#x63;&#x72;&#x69;&#x70;&#x74;&#x3a;...   ← javascript: 的实体编码
```

> **深层原理(xss-labs 第8关,必须吃透)**:
> 浏览器解析 HTML 分两阶段——**先认结构(用原始 `<` `>` 认标签),后解码实体(把 `&#x6a;` 解成字符)**。
> - **防御方把 `<` 实体化能防住 XSS**:因为认结构在解码之前,`&lt;` 在认结构时是普通字符(还没解码),结构定死没有新标签;解码后那个 `<` 来晚了,只能当文字 → 伪造标签失败。
> - **攻击方把 `javascript` 实体化却能绕过**:因为它不伪造标签,而是在**已有的 href 属性值**里藏关键字,而 href 的值"在解码之后才被当协议处理",正好赶上。
> - **关键区分**:同一个实体编码技术,**防御方编码"破坏结构的符号(`<`)"让 payload 死,攻击方编码"躲避检测的关键字(javascript)"让 payload 活。**
> - **为什么必须用 HTML 实体 `&#x6a;` 而非 JS 的 `\u006a` 或 URL 的 `%6a`**:因为 payload 落在 HTML 属性里,解析它的是 **HTML 解析器**,只认 HTML 实体。`\u` 是 JS 引擎的、`%` 是 URL 层的,HTML 解析器不认。**判断编码能否绕过,核心是问:payload 落在哪个解析环境(HTML/JS/URL),那个环境会不会解码我用的编码。**

> ⚠️ 澄清:`&#x6a;` 的正式名字是 **HTML 实体编码(数字字符引用)**,不是"Unicode 编码"——只是内部数字恰好是 Unicode 码点,俗称不精确。

### 2.6 分隔符绕过(空格/斜杠被过滤,打不了属性)🔴

**场景**:过滤器把"标签名和属性之间的空格/`/`"清空或替换成 `&nbsp;`,让你没法给标签加事件属性。
**技巧**:HTML 认可的"分隔符"不止空格,换一个过滤器没覆盖的空白字符。

```
<svg%09onload=alert(1)>   ← %09 Tab
<svg%0aonload=alert(1)>   ← %0a 换行 LF
<svg%0conload=alert(1)>   ← %0c 换页 FF(xss-labs 第15、20关的答案)
<svg%0donload=alert(1)>   ← %0d 回车 CR
```

> **原理**:HTML 解析器把空格、Tab、换行、换页、回车**这一整类空白字符**都当作"标签名和属性之间的合法分隔符"。过滤器开发者往往只想到"空格"和"`/`",漏了 Tab/换行/换页/回车。`%0c`(换页)是最经典的漏网之鱼。

### 2.7 无括号调用(括号 `()` 被吃掉)🔴

**场景**:过滤器清空所有小括号 `()`,`alert(1)` 变成 `alert1`,没法调用函数。
**技巧**:用**反引号**代替括号调用函数(JS 的"标签模板"语法)。

```
<svg onload=alert`1`>   ← alert`1` 等价于 alert('1'),用反引号不用括号
```

> **原理**:JavaScript 里,函数名后面直接跟一个反引号模板字符串,等于用该字符串作参数调用这个函数(Tagged Template 语法)。`alert\`1\`` 真的会执行 alert。既然过滤只吃括号、不吃反引号,就用反引号调用。

### 2.8 JS 字符串逃逸(输入在 JS 代码的字符串里)🔴

**场景**:输入被拼进一段 JS 代码的字符串里,如 `var k='你的输入'`,且尖括号被转义(打不了 HTML 标签)。
**技巧**:闭合单引号逃出字符串,直接写 JS,用 `//` 注释掉原代码尾巴。

```
';alert(1);//
```
代入 `var k='';alert(1);//';`:
- `'` 闭合字符串 → `;` 结束语句 → `alert(1)` 独立执行 → `//` 注释掉原来的 `';`

> **关键认知**:注入点不只在 HTML 里,也可能在 JS 代码里。输入落在 JS 字符串中时,尖括号被转义**没关系**——你根本不需要打标签,闭合引号直接写 JS 就行。这防的是 HTML 注入,没防 JS 字符串逃逸。

### 2.9 DOM 型(Source→Sink,前端 JS 造成)🔴

**场景**:前端 JS 把 URL 里的内容(如 `location.hash`)未经过滤写进 `innerHTML`。
**技巧**:payload 放 URL 的 `#` 后面,用事件标签。

```
#<img src=x onerror=alert(1)>     ← 放 hash 里,innerHTML 解析触发
```

> **两个关键细节**:
> ① **payload 放 `#` 后面**:hash 不发给服务器,纯前端处理("后端什么都不做")。
> ② **innerHTML 不执行 `<script>`**:浏览器安全机制——innerHTML 塞进来的 `<script>` 不运行。所以**必须用带事件的标签**(`<img onerror>`/`<svg onload>`),不能用 `<script>`。

## 3. 各关卡速查表(按过滤类型 → 绕过技巧)

| 过滤器做了什么 | 盲区 | 绕过技巧 | payload 示例 |
|---|---|---|---|
| 无过滤 | — | 直接打 | `<script>alert(1)</script>` |
| 输入在属性里,没过滤引号 | — | 闭合+事件 | `" onfocus=alert(1) autofocus` |
| 尖括号实体化,输入在属性里 | — | 闭合引号+事件(打不了新标签) | `" onfocus=alert(1) autofocus` |
| 过滤事件关键字 | 换入口 | 伪协议 | `<a href=javascript:alert(1)>x</a>` |
| 正则没管大小写 | 大小写 | 大小写混写 | `<sCript>alert(1)</sCript>` |
| 关键字只删一次 | 不回头 | 双写 | `<scrscriptipt>` |
| 关键字替换+htmlspecialchars,输入在 href | 不解码 | HTML 实体编码 | `href=&#x6a;...`（javascript:） |

| 真正可控点是隐藏参数 | 过滤盲区 | 找 hidden 参数注入 | `&t_sort=" ...` |

## 4. 防御视角:每个绕过对应的"正确防御"（🔴 核心,攻防对照）

> 理解防御,正好反过来告诉你绕过思路从哪来。作为渗透测试者,这也是你写修复建议的依据。

| 攻击/绕过 | 开发者为什么被绕过 | 正确防御 |
|---|---|---|
| 闭合引号/标签 | 输出到页面前没做编码 | **输出时实体化编码**(`<` `>` `"` `&` 转实体)——治本 |
| 大小写绕过 | 正则没加忽略大小写标志 | 正则加 `i` 标志;但黑名单本身就不可靠,应优先用白名单/编码 |
| 双写绕过 | `str_replace` 只删一次 | **循环删除直到不变**,或别用删除黑名单 |
| 编码绕过 | 只在字符串层过滤,没考虑浏览器解码 | 不要依赖关键字黑名单;用**输出编码**(DOMPurify 等成熟库) |
| 分隔符绕过 | 只过滤了空格/斜杠,漏了其他空白 | 别用黑名单堵分隔符;用白名单只允许预期的标签/属性 |
| 反引号绕括号 | 只过滤括号,没想到反引号调用 | 别靠过滤特定字符;根本上禁止用户输入进入可执行上下文 |
| JS 字符串逃逸 | 只转义了 HTML 尖括号,没处理 JS 字符串边界 | 用户输入进 JS 时,用 `JSON.stringify` 或专门的 JS 编码,别裸拼 |
| DOM 型 | 前端用 innerHTML 处理用户输入 | 前端用 `textContent` 代替 `innerHTML`;必须插 HTML 时用 DOMPurify 净化 |

> **一句话防御总结**:**所有这些绕过能成立,根子都是开发者用了"黑名单过滤"(堵特定字符/关键字)。而黑名单天生有漏洞(总有没堵到的点)。真正的防御是"输出编码 + 白名单",从根上让用户输入无法进入可执行上下文,而不是一个个去堵。**

## 5. 几个最有价值的思考(这些比 payload 更值钱)

### 5.1 "能通关 ≠ 真正打通漏洞"(level 14 的教训)

在 level 14,直接在 Console 敲 `alert()` 能通关,但那**不是真正利用了漏洞**——Console 本来就能执行任意 JS,是你自己(页面所有者)在执行,不是"攻击者的 JS 在受害者页面执行"。真正的 XSS 是"让别人的页面执行我的代码"。
> **这个分辨能力在真实 Bug Bounty 里很关键**:"我 Console 敲 alert 弹窗了"不是漏洞,会被平台拒;"我构造恶意链接,受害者访问后 alert 自动执行"才是真漏洞。**区分"假 XSS(自己执行)"和"真 XSS(让别人页面执行)"。**

### 5.2 "先认结构后解码"是理解一切编码绕过的总钥匙

浏览器解析 HTML 先认结构、后解码实体;Vue 先编译模板、后填数据——**都是"处理流程分前后两步,你的 payload 能不能生效,取决于它赶没赶上关键的那一步"。** 防御方实体化 `<` 能防住(`<` 来晚了当不成标签),攻击方实体化关键字能绕过(关键字藏在解码后仍生效的位置)。这套"时机决定命运"的思维,是 XSS 绕过的底层逻辑,也能迁移到 Vue 模板注入等场景。

### 5.3 诊断思维 > 背 payload

整个 xss-labs,真正让我每关都能破的,不是记住 payload,而是**每关都先看 F12 里"过滤器把我改成了什么样",再对症换招**。payload 网上一搜一大把,但"看过滤结果反推该用什么招"的判断力,是换任何靶场/真实目标都带得走的。**失败的 payload 不是终点,是暴露过滤规则的信息。**

### 5.4 注入点不只在 URL 参数里

level 11 的 Referer 注入教会我:**请求头(Referer/User-Agent/Cookie)也是用户可控的输入点。** 当某个值"有内容但改 URL 改不动它"时,要想到它可能来自请求头,用 Burp 去改。这呼应《HTTP请求头注入面》笔记。

### 5.5 在 Burp 里看到注入成功,就已证明漏洞

level 11,在 Repeater 响应里看到 payload 成功闭合、注入进 HTML,就已经证明漏洞成立——Repeater 只收发文本不渲染,不弹窗不代表没漏洞。真实渗透中,"payload 可控注入进了响应"就是有效证据,不必非要浏览器真弹窗。

## 6. 自测(先自己想,再看答案)

1. 同样是"闭合引号",为什么在 `<input value="输入">`(HTML 环境)和 `var k='输入'`（JS 环境)里,闭合后的打法完全不同?
2. 为什么防御方把 `<` 实体化成 `&lt;` 能防住 XSS,而攻击方把 `javascript` 实体化却能绕过过滤?(用"先认结构后解码"解释)
3. 一关把空格和 `/` 都清空了,让你没法给标签加属性。你有哪些"分隔符"可以替代?背后的原理是什么?

<details>
<summary>参考答案</summary>

1. 因为环境不同,执行 JS 的方式不同。HTML 环境里,闭合引号后你在 HTML 中,**HTML 不能直接执行 JS,必须靠事件属性**(`onfocus=alert()`),裸写 alert 只会变成废属性。JS 环境里,闭合引号后你已经在 JS 代码中,**直接写 alert() 就执行**。核心:HTML 环境加事件,JS 环境直接写 JS。
2. 因为浏览器"先认结构、后解码"。防御方的 `&lt;`:认结构阶段它是普通字符(没解码),结构定死没有新标签;解码阶段它才变 `<`,但认标签窗口已关,只能当文字——伪造标签失败。攻击方的 `javascript` 实体:它不伪造标签,而是藏在已有的 href 属性值里,而 href 值"在解码之后才被当协议处理",正好赶上执行时机。区别:防御编码"结构符"让payload死,攻击编码"关键字"让payload活。
3. 可替代空格的分隔符:`%09`(Tab)、`%0a`(换行LF)、`%0c`(换页FF)、`%0d`(回车CR)。原理:HTML 解析器把这一整类空白字符都当作"标签名和属性之间的合法分隔符",而过滤器开发者往往只堵了空格和 `/`,漏了这些隐形空白。`%0c` 是最经典的漏网之鱼。

</details>
