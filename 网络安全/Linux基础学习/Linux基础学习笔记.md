> 定位：这份文档的目标是让你**不看任何视频教程**，只靠这一份文档就能学会Linux基础操作，具备独立在Kali环境里完成日常操作、为后续Web安全学习打基础的能力。
>
> 使用方法：每一节先看"概念"搞懂原理，再对照"命令详解"动手敲一遍，最后做"实操练习"巩固。不要只看不练，Linux是练出来的，不是看会的。

> 学习顺序：基础命令 → 文件系统 → 用户与权限 → 网络基础 → Shell脚本 → 系统运维 → 服务部署

## 一、基础命令

### 1.1 pwd — 查看当前路径

**概念**：Linux的命令行没有像Windows资源管理器那样的可视化"你在哪"提示，所以你需要随时用 `pwd`（print working directory）确认自己当前所在的目录，避免在错误的位置执行删除等危险操作。

```bash
pwd
# 输出示例: /home/kali/Desktop
```

无常用参数，记住用法即可。

---

### 1.2 ls — 列出目录内容

**概念**：`ls`（list）用来查看当前目录下有哪些文件和子目录，是使用频率最高的命令之一。

```bash
ls
```

| 参数 | 说明 | 示例 |
|---|---|---|
| `-l` | 详细信息（长格式：权限、属主、大小、修改时间） | `ls -l` → `-rw-r--r-- 1 kali kali 220 7月16 10:00 file.txt` |
| `-a` | 显示所有文件，包括隐藏文件（`.` 开头） | `ls -a` → 会显示 `.bashrc`、`.ssh` 这类隐藏文件 |
| `-la` / `-al` | 组合用法，最常用，详细信息+隐藏文件都显示 | `ls -la /home/kali` |
| `-h` | 配合 `-l` 使用，把文件大小转成人类可读格式(K/M/G) | `ls -lh` → 显示 `4.0K` 而不是 `4096` |
| `-R` | 递归列出所有子目录内容 | `ls -R /etc` |
| `-t` | 按修改时间排序（最新的在前） | `ls -lt` → 看最近改动过的文件 |
| `-S` | 按文件大小排序（从大到小） | `ls -lS` → 找出目录里最大的文件 |
| `-1` | 每行只显示一个文件名（适合配合脚本处理） | `ls -1 *.txt` |

**实战常用组合**：`ls -lah`（详细+隐藏+人类可读大小，是查看目标机器文件时最常用的组合）

**怎么读 `ls -l` 的输出**（这是后面权限章节的基础，一定要看懂）：
```
-rw-r--r-- 1 kali kali 220 7月16 10:00 file.txt
```
从左到右依次是：文件类型和权限位 / 硬链接数 / 属主 / 属组 / 文件大小 / 修改时间 / 文件名。权限部分会在第三章详细展开。

**实操练习**：在家目录下执行 `ls -la`，观察有哪些以 `.` 开头的隐藏配置文件（如 `.bashrc`），试着用 `cat` 打开看看里面写了什么。

---

### 1.3 cd — 切换目录

**概念**：Linux路径分两种——**绝对路径**（从根目录 `/` 开始写完整路径，如 `/home/kali/Desktop`）和**相对路径**（相对于你当前所在位置，如 `cd Desktop`）。搞清楚这个区别，才能理解 `cd` 的用法。

```bash
cd 目录路径          # 切换到绝对路径（从根目录/开始的完整路径）
cd 子目录名          # 切换到当前目录下的子目录（相对路径）
cd ..                # 返回上一级目录
cd ../..             # 返回上两级目录
cd ~   或直接  cd     # 回到当前用户的家目录
cd -                 # 回到上一次所在的目录（在两个目录间来回切换很好用）
```

**实操练习**：从家目录开始，用 `cd` 一路走到 `/var/log`，再用 `cd -` 秒回家目录，体会绝对路径和相对路径的区别。

### 1.4 mkdir / touch — 创建目录与文件

```bash
mkdir 目录名
```

| 参数 | 说明 | 示例 |
|---|---|---|
| `-p` | 递归创建多级目录（父目录不存在也会自动创建） | `mkdir -p project/src/utils` 一次性建好三层目录 |
| `-v` | 显示创建过程 | `mkdir -v newdir` → 输出"已创建目录 'newdir'" |

```bash
touch 文件名                    # 文件不存在则创建空文件，存在则只更新修改时间
touch -t 时间戳 文件名            # 指定修改时间，时间戳格式为 年月日时分（如 202501010000）
```

---

### 1.5 cp / mv / rm — 复制、移动、删除

**cp — 复制文件/目录**

```bash
cp 源文件 目标路径
```

| 参数 | 说明 | 示例 |
|---|---|---|
| `-r` / `-R` | 递归复制，**复制目录必须加**，否则会报错 | `cp -r sourcedir destdir` |
| `-v` | 显示复制过程（verbose） | `cp -rv dir1 dir2` |
| `-i` | 目标文件已存在时询问是否覆盖 | `cp -i a.txt b.txt` |
| `-p` | 保留原文件的权限、时间戳等属性 | `cp -p config.conf /backup/` |
| `-u` | 只在源文件比目标新，或目标不存在时才复制 | `cp -u *.log /backup/` |

**mv — 移动 / 重命名**（Linux没有单独的rename命令，同目录下用mv就是改名）

```bash
mv 原文件名 新文件名        # 同目录下用于重命名
mv 文件名 目标目录路径      # 移动到其他目录
```

| 参数 | 说明 | 示例 |
|---|---|---|
| `-i` | 覆盖前询问 | `mv -i a.txt b.txt` |
| `-v` | 显示移动过程 | `mv -v *.txt /tmp/` |
| `-n` | 目标已存在时不覆盖 | `mv -n file.txt /backup/` |

**rm — 删除文件/目录**

```bash
rm 文件名
```

| 参数 | 说明 | 示例 |
|---|---|---|
| `-r` | 递归删除（删除目录必须加） | `rm -r dirname` |
| `-f` | 强制删除，不提示确认（force） | `rm -f file.txt` |
| `-rf` | **组合使用最常见，也最危险**，递归+强制，没有确认也没有回收站 | `rm -rf dirname` |
| `-i` | 每次删除都询问确认（新手建议养成习惯） | `rm -i *.txt` |

> ⚠️ **重要安全提醒**：`rm -rf /` 或在错误目录下执行 `rm -rf *` 是新手最容易踩的坑，会导致系统文件被清空且无法恢复。**执行任何 `rm -rf` 之前，先用 `pwd` 确认自己在哪个目录**，这是一个应该刻进肌肉记忆的习惯。

**实操练习**：新建一个测试目录，在里面创建几个文件，练习用cp复制、mv改名、rm删除，全程养成"删除前先pwd确认位置"的习惯。

### 1.6 查看文件内容：cat / less / head / tail

**概念**：这四个命令都是"看文件内容"，区别在于**看多少、怎么看**。文件小用cat，文件大或日志文件用less/tail。

**cat — 一次性输出全部内容**（适合小文件，大文件会刷屏刷不过来）

```bash
cat 文件名
```

| 参数 | 说明 | 示例 |
|---|---|---|
| `-n` | 显示行号 | `cat -n script.sh` |
| `-A` | 显示所有不可见字符（排查Windows/Linux换行符问题时常用） | `cat -A file.txt` |

**less — 分页查看**（大文件、配置文件首选，不会刷屏）

```bash
less 文件名
```
打开后的交互键（不是命令行参数，是进入less界面后的操作）：

| 按键 | 作用 |
|---|---|
| `空格` | 向下翻一页 |
| `b` | 向上翻一页 |
| `/keyword` | 向下搜索关键词，按 `n` 找下一个匹配，`N` 找上一个 |
| `q` | 退出 |

**head / tail — 看文件开头/结尾**

| 参数 | 说明 | 示例 |
|---|---|---|
| `-n N` | 显示前/后 N 行（默认10行） | `head -n 20 file.txt` / `tail -n 20 file.txt` |
| `-f` | 实时追踪文件末尾新增内容，**排查日志时必备** | `tail -f /var/log/auth.log` |

**实操练习**：用 `tail -f` 打开 `/var/log/auth.log`（或任意日志文件），另开一个终端窗口做点登录/sudo操作，观察日志实时刷新的效果。

### 1.7 grep — 文件内部的内容搜索

**概念**：`grep` 是在文件内容里按关键词搜索的工具，"翻文件内容找东西"几乎全靠它，安全工作里（比如在网站源码里找敏感信息）使用频率极高。(在文件里面搜索)

```bash
grep "关键词" 文件名
```

| 参数 | 说明 | 示例 |
|---|---|---|
| `-r` | 递归搜索整个目录 | `grep -r "password" /var/www/` |
| `-i` | 忽略大小写 | `grep -i "error" log.txt` |
| `-n` | 显示匹配内容所在的行号 | `grep -n "root" /etc/passwd` |
| `-v` | 反向匹配，显示**不包含**关键词的行 | `grep -v "^#" config.conf` （过滤掉注释行） |
| `-c` | 只统计匹配的行数，不显示内容 | `grep -c "404" access.log` |
| `-E` | 支持扩展正则表达式 | `grep -E "192\.168\.[0-9]+\.[0-9]+" log.txt` |
| `-w` | 精确匹配整个单词，避免匹配到子串 | `grep -w "admin" users.txt` |
| `--color` | 高亮显示匹配到的关键词 | `grep --color "error" log.txt` |

**实战组合**：`grep -rn "password" /var/www/` （递归查找源码里可能泄露的密码字符串，是渗透测试信息搜集阶段的常用命令）

**实操练习**：在 `/etc` 目录下用 `grep -rn "127.0.0.1"` 搜索一下，看看哪些配置文件里出现了这个字符串，理解grep是怎么定位内容的。

### 1.8 find — 文件查找	

**概念**：`ls` 是"看当前目录有什么"，`find` 是"按条件在整个文件系统里搜"，支持按文件名、类型、时间、大小、权限等多种条件组合查找，功能远比ls强大。(在目录中搜索)

```bash
find 搜索路径 -name "文件名"
```

| 参数 | 说明 | 示例 |
|---|---|---|
| `-name` | 按文件名查找（支持通配符 `*`） | `find / -name "*.conf"` |
| `-iname` | 按文件名查找，忽略大小写 | `find / -iname "*passwd*"` |
| `-type f` | 只找文件（f=文件, d=目录, l=软链接） | `find /var -type f -name "*.log"` |
| `-type d` | 只找目录 | `find / -type d -name "backup"` |
| `-mtime -1` | 查找最近N天内**修改过**的文件（`-1`表示1天内） | `find / -type f -mtime -1` |
| `-size +100M` | 按文件大小查找（`+`大于，`-`小于） | `find / -size +100M` （找大文件） |
| `-perm` | 按权限查找 | `find / -perm -4000` （**找SUID提权文件，渗透常用**） |
| `-exec` | 找到结果后对每个结果执行命令 | `find / -name "*.tmp" -exec rm {} \;` |

**实战组合**：`find / -perm -4000 -type f 2>/dev/null`（查找具有SUID权限的文件，是Linux权限提升信息搜集阶段的经典命令，建议直接记住这一整条）。命令末尾的 `2>/dev/null` 是把权限报错信息丢弃，只看有效结果，这个技巧后面很常用。

**实操练习**：执行上面这条SUID查找命令，看看Kali系统里默认哪些程序带有SUID位。

### 1.9 进程与系统状态

**概念**：Linux里所有正在运行的程序都叫"进程"（process），每个进程有唯一的PID（进程ID）。查看、监控、结束进程是日常运维和排查问题的基本功。

**ps — 查看进程快照**

```bash
ps aux
```

| 参数 | 说明 |
|---|---|
| `a` | 显示所有用户的进程 |
| `u` | 显示进程所属用户和详细资源占用（CPU/内存占比） |
| `x` | 包含没有控制终端的进程（如后台服务） |
| `-ef` | 另一种常见格式，显示完整命令行参数 |

**实战组合**：`ps aux | grep 关键词`（配合grep查找特定进程，比如 `ps aux | grep mysql` 看MySQL进程是否在跑，以及它的PID）

**top / htop — 实时监控**

```bash
top     # 系统自带，按 q 退出，按 P 按CPU占用排序，按 M 按内存占用排序
htop    # 需要 apt install htop，界面更直观，支持鼠标操作，建议装
```

**kill — 结束进程**

| 参数 | 说明 | 示例 |
|---|---|---|
| （不加参数） | 发送默认终止信号(15/SIGTERM)，礼貌地让进程自己退出 | `kill 1234` |
| `-9` | 强制杀死进程(SIGKILL)，进程无法拒绝，立即终止 | `kill -9 1234` |
| `-l` | 列出所有可用信号 | `kill -l` |

也可以直接按进程名杀，不用先查PID：`killall firefox`

**磁盘与内存**

```bash
df -h                          # 查看磁盘空间占用（-h 人类可读格式）
du -sh 目录名                    # 查看指定目录总大小（-s 只显示总计，不列子目录）
du -h --max-depth=1 /var         # 查看/var下每个子目录各占多大，排查磁盘占满问题常用
free -h                        # 查看内存使用情况
```

**实操练习**：执行 `ps aux | grep bash`，找到当前终端对应的bash进程PID，理解PID和进程的对应关系。

## 二、文件系统结构

### 2.1 概念

Linux是"一切皆文件"的**单根树状结构**，跟Windows的C盘D盘完全不同——没有盘符，只有一个根目录 `/`，所有硬盘、分区、设备都以"挂载"的方式挂到这棵树的某个目录下。理解这一点，你就能明白为什么Linux里"文件路径"这么重要。

### 2.2 关键目录速查表

| 目录 | 作用 |
|---|---|
| `/etc` | 系统与软件的配置文件，几乎所有服务的配置都在这里（如 `/etc/passwd` 用户信息、`/etc/ssh/sshd_config` SSH配置） |
| `/home` | 普通用户的家目录，每个用户一个子目录，如 `/home/kali` |
| `/root` | root用户专属的家目录（注意不在 `/home` 下） |
| `/var` | 经常变动的数据，最重要的是日志目录 `/var/log`，排查问题第一站 |
| `/bin`, `/usr/bin` | 系统与用户命令的可执行文件存放处（`ls`、`cat` 这些命令本身就在这里） |
| `/sbin`, `/usr/sbin` | 系统管理类命令（通常需要root权限执行） |
| `/dev` | 设备文件，硬盘、USB、终端等硬件在Linux里都表现为文件 |
| `/proc` | 内核和进程的运行时信息，是虚拟文件系统，不是真实存在磁盘上的文件（比如 `/proc/cpuinfo` 能看CPU信息） |
| `/tmp` | 临时文件目录，重启后会被清空，任何用户都可写 |
| `/opt` | 第三方软件的可选安装目录 |
| `/mnt`, `/media` | 手动/自动挂载外部设备（U盘、光盘）的位置 |

### 2.3 文件类型

`ls -l` 输出第一位字符表示文件类型：

| 符号 | 类型 |
|---|---|
| `-` | 普通文件 |
| `d` | 目录（directory） |
| `l` | 软链接（symbolic link，类似Windows快捷方式） |

**实操建议**：用 `ls -la /` 把根目录下每个子目录都进去看一眼，再用 `cat /etc/os-release` 看当前发行版信息，用 `cat /proc/cpuinfo` 感受一下`/proc`这种"虚拟文件"的概念，建立起对整个目录树的空间感。

## 三、用户与权限

### 3.1 用户体系概念

Linux是多用户系统，每个用户有自己的家目录和权限范围。系统里有一个权限最高的超级用户 **root**，日常操作不建议直接用root登录（避免误操作破坏系统），而是用普通用户配合 `sudo` 临时提权执行需要管理员权限的命令。

```bash
whoami                  # 查看当前登录用户
id                     # 查看用户ID(UID)和所属组(GID)
su 用户名                # 切换到指定用户（需要目标用户的密码）
sudo 命令                # 以管理员权限执行单条命令（需要当前用户的密码，且必须在sudoers列表里）
sudo -i                  # 切换到root的交互式shell（相当于长期获得root权限）
adduser 新用户名           # 添加新用户（Debian/Kali系，交互式，会引导设置密码等信息）
useradd 新用户名           # 添加新用户（更底层的命令，不会自动创建家目录，通常配合adduser用更省心）
passwd 用户名             # 修改指定用户密码
usermod -aG 用户组名 用户名  # 把用户加入某个用户组（-aG 表示追加到组，不会覆盖原有组）
groups 用户名             # 查看用户所属的所有组
```

**su 和 sudo 的区别**（面试常问）：`su` 是切换到另一个用户身份，需要**目标用户**的密码；`sudo` 是以当前用户身份临时借用管理员权限执行命令，需要**当前用户自己**的密码，且执行完命令后自动恢复普通权限，相对更安全，也是Kali/Ubuntu里更推荐的方式。

### 3.2 权限体系（重点，面试和实操都常考）

**概念**：Linux给每个文件/目录都定义了三类身份的权限——**属主(owner)、属组(group)、其他人(others)**，每类身份又分**读(r)、写(w)、执行(x)**三种权限。

用 `ls -l` 看到类似 `-rwxr-xr--` 这样的字符串，拆解如下：

```
-   rwx   r-x   r--
类型 属主  属组  其他人
```

- 第1位：文件类型（`-`普通文件，`d`目录，`l`软链接）
- 接下来3位一组，分别是**属主(u) / 属组(g) / 其他人(o)** 的权限
- `r`（读=4）`w`（写=2）`x`（执行=1），每组权限值相加就是常见的数字表示法

**权限对目录和文件的含义不完全一样**：对文件，`r`是能否查看内容，`w`是能否修改，`x`是能否作为程序执行；对目录，`r`是能否列出目录内容(ls)，`w`是能否在目录里创建/删除文件，`x`是能否**进入**该目录(cd)。这个区别容易被忽略，但很重要——比如一个目录只有 `r` 没有 `x`，你能看到里面文件名但没法 `cd` 进去。

**chmod — 修改权限**

数字模式（更常用，速度快）：

| 数字 | 含义 | 示例 |
|---|---|---|
| `755` | 属主读写执行(7)，属组读+执行(5)，其他人读+执行(5) | `chmod 755 script.sh` （脚本常用：自己能改能跑，别人能跑不能改） |
| `644` | 属主读写(6)，属组只读(4)，其他人只读(4) | `chmod 644 config.txt` （普通配置文件常用） |
| `777` | 所有人读写执行 | `chmod 777 file` （⚠️ 权限完全开放，非必要不要用，是常见的错误配置类漏洞） |
| `600` | 只有属主能读写，其他人无任何权限 | `chmod 600 id_rsa` （SSH私钥文件的标准权限，权限过松SSH会拒绝使用该私钥） |

符号模式（更直观，适合微调单一权限）：

| 参数 | 说明 | 示例 |
|---|---|---|
| `u` `g` `o` `a` | 属主/属组/其他人/所有人 | `chmod u+x file.sh` 只给属主加执行权限 |
| `+` `-` `=` | 增加/去掉/精确设置权限 | `chmod g-w file.sh` 去掉属组的写权限 |
| `-R` | 递归修改（对目录下所有文件/子目录生效） | `chmod -R 755 /var/www/html` |

**chown — 修改属主/属组**

```bash
chown 用户名:用户组 文件名      # 同时改属主和属组
chown 用户名 文件名            # 只改属主
chown :用户组 文件名           # 只改属组
chown -R 用户名:用户组 目录名   # 递归修改整个目录及其内容
```

**了解即可：特殊权限位**（后面学Web安全时会遇到，先眼熟）

- **SUID**：文件执行时临时获得属主的权限，常见于 `passwd` 这类需要临时提权的命令，`find / -perm -4000` 就是在找带SUID的文件，是提权信息搜集的经典手法
- **Sticky Bit**：常见于 `/tmp` 目录，让每个用户只能删除自己创建的文件

**实操练习**：新建一个脚本文件，不给执行权限直接运行，观察报的 `Permission denied` 错误，再用 `chmod +x` 加上执行权限重新运行，对比理解权限如何生效。

## 四、网络基础

### 4.1 概念

这一章是"在命令行里做网络工程课上学的事"——查看网卡配置、测试连通性、查端口、查DNS，是后续学习安全工具（nmap、wireshark）之前必须打牢的地基。

### 4.2 命令详解

**ip — 查看/配置网络（新一代命令，替代老的ifconfig）**

```bash
ip a                       # 查看所有网卡的IP地址（等价于旧版 ifconfig）
ip addr show 网卡名          # 只看指定网卡的信息
ip route                    # 查看路由表，判断数据包往哪个网关走
ip addr add IP地址/子网掩码位数 dev 网卡名   # 给网卡临时配置一个固定IP（重启后失效，需要写进配置文件才能持久化）
ip link set 网卡名 up         # 启用网卡
ip link set 网卡名 down        # 禁用网卡
```

**ping — 测试连通性**

```bash
ping 目标地址
```

| 参数 | 说明 | 示例 |
|---|---|---|
| `-c N` | 只发送N次探测包后自动停止（不加会一直发送，需要手动Ctrl+C） | `ping -c 4 baidu.com` |
| `-i N` | 设置发包间隔秒数 | `ping -i 2 baidu.com` |

**curl — 发起HTTP请求（渗透和调试接口常用）**

```bash
curl 目标URL
```

| 参数 | 说明 | 示例 |
|---|---|---|
| `-I` | 只看响应头，不下载正文内容 | `curl -I https://example.com` |
| `-o filename` | 把响应内容保存为指定文件名 | `curl -o page.html https://example.com` |
| `-O` | 用URL里的原文件名保存（常用于下载文件） | `curl -O https://example.com/file.zip` |
| `-X` | 指定请求方法（GET/POST/PUT等） | `curl -X POST https://example.com/api` |
| `-d` | 发送POST数据 | `curl -X POST -d "user=admin" https://example.com/login` |
| `-H` | 自定义请求头 | `curl -H "User-Agent: test" https://example.com` |
| `-v` | 显示详细的请求/响应过程，排查问题用 | `curl -v https://example.com` |
| `-s` | 静默模式，不显示进度条 | `curl -s https://example.com` |

**wget — 专注下载文件**

```bash
wget 目标文件URL
```

**netstat / ss — 查看端口占用和网络连接**（ss是netstat的现代替代品，速度更快，推荐优先用ss）

```bash
netstat -tulnp     # 可能需要 apt install net-tools
ss -tulnp
```

参数含义（两个命令通用）：

| 参数 | 说明 |
|---|---|
| `-t` | 显示TCP连接 |
| `-u` | 显示UDP连接 |
| `-l` | 只显示监听中(listening)的端口 |
| `-n` | 用数字显示地址和端口，不做域名反查（速度更快） |
| `-p` | 显示占用该端口的进程名和PID |

**实战组合**：`ss -tulnp`（一次性看清本机所有正在监听的端口以及对应的进程，排查"这个端口是谁开的"必用）

**dig / nslookup — DNS查询**

```bash
dig 域名                 # 更详细，渗透测试首选
nslookup 域名             # 更简单直观
```

**实操练习**：执行 `ss -tulnp` 查看本机当前开放了哪些端口，对照第六章的常见端口表，看看能不能认出SSH、MySQL等服务分别监听在哪个端口。

## 五、Shell 脚本基础

### 5.1 概念

**Shell脚本**就是把一系列命令按顺序（或带条件判断、循环逻辑）写进一个文本文件，交给Shell解释器一次性批量执行，本质上是"把你在命令行里手敲的操作自动化"。学会写脚本之后，你可以自动化很多重复性工作（比如批量测试端口、批量处理文件、写简单的信息搜集脚本）。

### 5.2 变量

```bash
name="折酒"          # 定义变量，等号两边不能有空格（这是常见的语法错误来源）
echo "Hello, $name"   # 使用变量要加 $ 符号，建议用双引号包裹避免出问题
echo "Hello, ${name}"  # ${} 是更规范的写法，尤其是变量后面紧跟其他字符时（如 ${name}_suffix）
```

### 5.3 条件判断

```bash
if [ -f "$1" ]; then
    echo "文件存在"
elif [ -d "$1" ]; then
    echo "是一个目录"
else
    echo "都不是"
fi
```

`[ ]` 里常用的判断条件（是脚本里最容易记混的部分，建议做个小抄）：

| 条件 | 含义 | 示例 |
|---|---|---|
| `-f file` | 文件存在且是普通文件 | `[ -f "$1" ]` |
| `-d dir` | 目录存在 | `[ -d "$1" ]` |
| `-e path` | 路径存在（不区分文件还是目录） | `[ -e "$1" ]` |
| `-z string` | 字符串为空 | `[ -z "$name" ]` |
| `-n string` | 字符串不为空 | `[ -n "$name" ]` |
| `s1 = s2` | 两个字符串相等 | `[ "$a" = "$b" ]` |
| `s1 != s2` | 两个字符串不相等 | `[ "$a" != "$b" ]` |
| `-eq` `-ne` | 数字相等 / 不相等 | `[ "$num" -eq 10 ]` |
| `-gt` `-lt` | 数字大于 / 小于 | `[ "$num" -gt 5 ]` |
| `-ge` `-le` | 数字大于等于 / 小于等于 | `[ "$num" -ge 5 ]` |

> ⚠️ 变量一定要用双引号包裹，比如写成 `[ -f "$1" ]` 而不是 `[ -f $1 ]`——如果变量值包含空格或者本身是空值，不加引号会导致脚本报错甚至逻辑出错，这是新手最常踩的坑之一。

### 5.4 循环

```bash
# for 循环：已知要循环几次或遍历一组值
for i in 1 2 3; do
    echo "第 $i 次"
done

for file in *.txt; do
    echo "处理文件: $file"
done

# while 循环：不确定循环次数，只要条件成立就一直执行
count=1
while [ $count -le 5 ]; do
    echo "计数: $count"
    count=$((count + 1))    # Shell里数字运算要用 $(( )) 包裹
done
```

### 5.5 函数

```bash
say_hello() {
    echo "你好, $1"    # $1 是函数接收的第一个参数
}

say_hello "折酒"       # 调用函数，输出：你好, 折酒
```

### 5.6 脚本参数与用户输入

```bash
#!/bin/bash
# 脚本名: test.sh
echo "脚本名: $0"       # $0 是脚本自身的名字
echo "第一个参数: $1"    # $1 $2 $3... 是调用脚本时传入的参数
echo "所有参数: $@"      # $@ 是所有参数
echo "参数个数: $#"      # $# 是参数总数

read -p "请输入你的名字: " username    # 读取用户手动输入
echo "你好, $username"
```

调用方式：`./test.sh 参数1 参数2`

### 5.7 完整示例：写一个简单的端口存活检测脚本

```bash
#!/bin/bash
# 用法: ./check_port.sh 目标IP 端口号

target=$1
port=$2

if [ -z "$target" ] || [ -z "$port" ]; then
    echo "用法: $0 <IP> <端口>"
    exit 1
fi

timeout 2 bash -c "echo > /dev/tcp/$target/$port" 2>/dev/null

if [ $? -eq 0 ]; then
    echo "$target:$port 端口开放"
else
    echo "$target:$port 端口关闭或不可达"
fi
```

保存为 `check_port.sh`，然后：

```bash
chmod +x check_port.sh
./check_port.sh 127.0.0.1 22
```

这个小脚本把前面学的条件判断、变量、参数全用上了，也是一个非常贴近安全场景的实用小工具，建议自己敲一遍加深理解。

**学习顺序建议**：变量 → 条件判断 → 循环 → 函数 → 脚本参数 → 尝试自己写一个小工具脚本（比如批量检测多个端口、批量重命名文件），比死记语法有效得多。

## 六、系统运维基础

> 优先级标记：✅ 必学　⚪ 了解即可

### 6.1 软件包管理

```bash
apt update                # ✅ 更新软件源列表（安装新软件前一般先执行这个）
apt upgrade                # 升级已安装的软件包
apt install 软件包名         # ✅ 安装软件（Debian/Kali系）
apt remove 软件包名          # 卸载软件（保留配置文件）
apt purge 软件包名           # 彻底卸载（连配置文件一起删）
apt search 关键词            # 搜索软件包
apt list --installed        # 查看已安装的软件包列表
```

### 6.2 服务管理 systemctl

**概念**：Linux里长期运行的后台服务（MySQL、Nginx、SSH等）都由 `systemd` 这个系统统一管理，`systemctl` 是操作它的命令。

```bash
systemctl start 服务名        # ✅ 启动服务（如 mysql、nginx）
systemctl stop 服务名         # 停止服务
systemctl restart 服务名      # 重启服务（改完配置文件后常用）
systemctl reload 服务名       # 重新加载配置但不中断服务（比restart更平滑，配置支持的情况下优先用这个）
systemctl status 服务名       # ✅ 查看服务状态（运行中/已停止/报错信息都在这里看）
systemctl enable 服务名       # 设置开机自启
systemctl disable 服务名      # 取消开机自启
```

### 6.3 主机名与固定IP配置

```bash
hostname                      # ✅ 查看主机名
hostnamectl set-hostname 新主机名   # 设置主机名
ip addr add IP地址/子网掩码位数 dev 网卡名   # ✅ 临时配置固定IP（重启失效，仅用于快速测试）
```

### 6.4 文件下载

```bash
curl -O 目标文件URL   # ✅ 下载文件（保留原文件名）
wget 目标文件URL      # ✅ 下载文件（另一常用工具，支持断点续传 -c 参数）
```

### 6.5 端口（安全领域核心概念，务必扎实）

| 端口 | 服务 |
|---|---|
| 22 | SSH |
| 80 / 443 | HTTP / HTTPS |
| 3306 | MySQL |
| 6379 | Redis |
| 9200 | Elasticsearch |
| 5672 | RabbitMQ |
| 8080 | Tomcat（默认） |

### 6.6 环境变量

```bash
echo $PATH                    # ⚪ 查看PATH环境变量（系统去哪些目录找可执行命令，就是靠这个变量）
export 变量名=值                # 临时设置环境变量（仅当前终端会话有效）
```

若要永久生效，需要把 `export` 语句写进 `~/.bashrc` 文件末尾，然后执行 `source ~/.bashrc` 让它立即生效。

### 6.7 文件传输与压缩

```bash
scp 本地文件 用户名@主机地址:目标路径       # ✅ 上传文件到远程主机（基于SSH，安全）
scp 用户名@主机地址:远程文件路径 本地目标路径  # 从远程主机下载文件
scp -r 本地目录 用户名@主机地址:目标路径     # 传输整个目录，需要加 -r
```

**tar 压缩解压详解**（记不住细节没关系，压缩记 `-zcvf`，解压记 `-zxvf` 这两组固定组合就够日常使用）：

```bash
tar -zcvf 压缩包名.tar.gz 目标目录/   # ✅ 压缩
tar -zxvf 压缩包名.tar.gz            # ✅ 解压
unzip 压缩包名.zip                  # 解压zip格式
```

| 参数 | 说明 | 示例 |
|---|---|---|
| `-c` | 创建压缩包（create） | `tar -cvf archive.tar dir/` |
| `-x` | 解压（extract） | `tar -xvf archive.tar` |
| `-z` | 通过gzip压缩/解压（生成/读取 .tar.gz） | `tar -zcvf a.tar.gz dir/` |
| `-v` | 显示压缩/解压过程（verbose） | 建议总是加上，方便确认进度 |
| `-f` | 指定文件名，**必须放在参数最后** | `tar -zcvf 目标.tar.gz 源目录/` |
| `-C` | 解压到指定目录 | `tar -zxvf a.tar.gz -C /opt/` |
| `-t` | 不解压，只查看压缩包里有哪些文件 | `tar -tvf a.tar.gz` |

**这一章建议节奏**：1周内压缩看完，重点吃透 systemctl、IP/端口配置、文件传输、压缩解压这几块，属于高频操作；软链接、日期时区、环境变量这些扫一眼建立印象即可。

## 七、服务部署（安全视角）

这部分对应常见课程里的 MySQL / Tomcat / Nginx / RabbitMQ / Redis / Elasticsearch 部署内容。**不是单纯的运维知识**——这几个服务本身就是Web安全里的经典漏洞靶子，学部署的同时要带着安全视角去理解：

| 服务 | 相关安全知识点 |
|---|---|
| MySQL | 弱口令、权限提升 |
| Redis | 未授权访问（经典漏洞，写SSH key/计划任务可getshell） |
| Elasticsearch | 未授权访问、RCE历史漏洞 |
| RabbitMQ | 默认口令（guest/guest） |
| Tomcat | 弱口令 + 后台管理界面getshell（PUT上传war包） |
| Nginx | 解析漏洞、配置错误（如目录穿越） |

**学习建议**：
- 每个服务只装一个能跑起来的版本即可，不需要CentOS和Ubuntu都装一遍
- MySQL 5.7/8.0选一个实操，了解另一版本区别就行
- 目标不是"精通生产级部署"，而是"能快速搭一个可以打的靶场环境"
- Docker部分你会自己学，这里不重复展开——搭好Linux基础后，用Docker起靶场会更快更规范

**这一章建议节奏**：1-2周，精简版部署即可，把重点放在理解每个服务对应的安全问题上，而不是死磕生产级部署细节。
