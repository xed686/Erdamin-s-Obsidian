## 0. 先建立一个认知框架:编排层 vs 执行层（🟡 重要，这个别过时）

市面上的 Agent 工具五花八门、更新飞快,但你只要抓住一个分层模型,就不会被具体工具绕晕:

```
【编排层 / 指挥官】  负责:理解大目标、拆解任务、决定谁来干、分层授权、委派
   例:Pi、Hermes
        ↓ 委派(delegate)
【执行层 / 干活的】  负责:具体执行某类任务(写代码、调试、审计某个文件)
   例:Claude Code、Codex、Devin
```

> 💡 **为什么这个框架比记工具名重要**:工具名半年就换一批,但"**有一个编排层统筹、把具体活委派给擅长的执行层**"这个模式是稳定的(这也正好对应上一篇讲的 Agent 本体"拆解目标→选合适的执行者"的闭环)。你理解了分工,再来一个新工具,看它是"指挥官"还是"干活的",就能立刻归位。

**这也呼应上一篇《MCP与Skill》的分层思想**——整个 Agent 世界到处是"分层":MCP(连接层)/Skill(流程层)/本体(大脑),现在工具生态又分编排层/执行层。**分层是复杂系统管理复杂度的通用手段**,看到分层就去问"每层负责什么、谁调谁"。

## 1. Pi（编排层 / Agent Harness）（🟢 了解）

> [!note] 🔎 已联网核实:Pi 是真实工具
> Pi(pi.dev)经非大陆来源确认真实存在——被描述为"**可扩展的 AI Agent harness**""**极简、可魔改(hackable)的 AI 编码 CLI**",支持子代理(subagents)、编排(orchestrator)、任务委派,读取 `AGENTS.md` 配置文件。和课程笔记描述一致。

### 1.1 定位与哲学

- **定位**:主打**单 Repo、代码审计、开发、安全审计、子代理委派**。
- **哲学**:轻、模块化、**权限分层**——这是对安全最关键的点:
  - `readonly`(只读)/ `edit`(可编辑)/ `danger`(危险操作)三级权限
  - 通过 `pi-harness-delegate` 把任务**委派**给 Claude Code、Codex、Devin 等执行层
- **入口**:本地 CLI,在项目目录下执行 `pi`,读取项目里的 `AGENTS.md`(类似给 Agent 的"项目说明书/规则")。

### 1.2 为什么"权限分层"对安全 Agent 是关键设计

这直接呼应上一篇讲的 **"过度授权(Excessive Agency)"攻击面**:

> 一个 Agent 如果权限过大、又没有分层约束,一旦被 prompt injection 劫持,就能执行破坏性操作。Pi 的 `readonly/edit/danger` 三级权限,正是用**权限分层**把 Agent 关进笼子——默认只读,要改文件才升到 edit,要做危险操作(删除、执行命令)才到 danger,每一级都可以卡审批。

**这和你学的"最小权限原则"是一回事**:给 Agent 的权限越小、分得越细,被劫持后能造成的破坏就越小。审计/渗透 Agent 操作的是敏感目标,权限分层尤其重要。

### 1.3 安全场景适用

课程列的 Pi 适用场景(都是红队/安全向):
- 红队源码审计、漏洞复现
- Go / .NET / Nim 红队工具开发(这几种语言常用于写免杀马/红队工具)
- MCP 插件开发
- 供应链加固

**入口**:官方 CLI(pi.dev)、桌面 UI 版(社区项目 `vastsa/PI-Desktop`)。

## 2. Claude Code（执行层 / 官方编码 Agent）（🟢 了解）

### 2.1 定位

- **定位**:Anthropic 官方编码 Agent,强在**代码理解、重构、调试、git 操作**。
- 绑定 Anthropic 模型生态(用 Claude 模型)。
- **关键**:它是**执行者,不是编排层**——Pi、Hermes 这些编排层可以**把任务委派给它**来干。

> 🔎 **对照框架理解**:Claude Code 就是上面那个分层模型里的"干活的"。你让 Pi(指挥官)去审计一个项目,Pi 可能把"重构这段代码""调试这个 bug"这类具体活**委派给 Claude Code**(执行层)来做。它干活强,但不负责统筹全局。
>
> (顺带一提——你现在整理这些笔记用的,正是 Claude Code 这类工具背后的能力。)

### 2.2 配套工具(🟢 了解)

- `cc-switch`(`farion1231/cc-switch`):Claude Code 的配置/模型切换工具。
- 汉化版桌面端等社区项目(课程提供了 B 站安装教程链接)。

> ⚠️ **待核实提醒**:课程提到的 `javaht/claude-desktop-zh-cn`、`farion1231/cc-switch` 等社区汉化/配套项目,我未用非大陆来源独立核实其安全性。**安装第三方汉化/魔改版工具有供应链风险**(可能被植入后门)——对一个搞安全的人来说,用来操作敏感项目的工具,更要确认来源可信,优先用官方版。

## 4. 一个安全视角的提醒(🔴 核心,别忽略)

作为一个搞渗透的人用这些 Agent 工具,有两个安全意识要始终在线:

1. **你用的 Agent 工具本身可能是攻击面**:
   - 第三方汉化/魔改版工具 → 供应链风险(可能被投毒)
   - 给 Agent 接的 MCP 插件 → 工具投毒风险(上一篇讲过)
   - 这正是"用安全的眼光看自己的工具链"——**搞安全的人,工具链被攻破是大忌**。

2. **权限分层不是麻烦,是保命**:
   - Pi 的 readonly/edit/danger 分层、委派时的审批,别图省事全开成 danger。
   - 用 Agent 操作真实目标(尤其授权渗透)时,**权限给到刚好够用就行**——万一 Agent 被诱导(prompt injection)做了越界操作,分层能兜底。

> **一句话**:你在学"攻击 AI 应用"(把 Agent 当靶子)的同时,自己用 Agent 工具时也要**把这套攻击面意识用在自己身上**——因为你用的工具,正是别人可能攻击你的入口。攻防视角要双向。
