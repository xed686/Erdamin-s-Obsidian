## 二、信息泄漏 - 源码文档 - 敏感配置监控

### 1. GitHub 监控

**GitHub 资源搜索语法：**

| 语法 | 说明 |
|---|---|
| `in:name test` | 仓库标题搜索含有关键字 |
| `in:description test` | 仓库描述搜索含有关键字 |
| `in:readme test` | Readme 文件搜索含有关键字 |
| `stars:>3000 test` | stars 数量大于 3000 |
| `stars:1000..3000 test` | stars 数量在 1000~3000 之间 |
| `forks:>1000 test` | forks 数量大于 1000 |
| `forks:1000..3000 test` | forks 数量在 1000~3000 之间 |
| `size:>=5000 test` | 仓库大于 5000k (5M) |
| `pushed:>2019-02-12 test` | 发布时间大于该日期 |
| `created:>2019-02-12 test` | 创建时间大于该日期 |
| `user:test` | 按用户名搜索 |
| `license:apache-2.0 test` | 按 LICENSE 搜索 |
| `language:java test` | 按代码语言搜索 |
| `user:test in:name test` | 组合搜索 |

**配合搜索引擎的关键字组合：**
```
site:Github.com smtp
site:Github.com smtp @qq.com
site:Github.com smtp @126.com
site:Github.com smtp @163.com
site:Github.com smtp @sina.com.cn
site:Github.com smtp password
site:Github.com String password smtp
```

**目标：**
- 系统源码：特征、文件等
- 敏感信息：密码、文档、人员等

**监控项目参考：**
- https://github.yhuisec.com/
- https://github.com/madneal/gshark
- https://github.com/NHPT/FireEyeGoldCrystal

## 三、供应链 - 目标旁路 - 获取和拓展

典型的迂回攻击方式：攻击者聚焦目标企业的上下游供应商（IT 供应商、安全供应商等），从中寻找软件、系统或管理上的漏洞，进而攻入目标企业内部。

**常见供应链切入点：**
- 商业购买系统
- 软件开发商
- 外包业务
- 代理商
- 招投标文件

**供应链打点例子（EDUSRC 挖洞思路）：**
1. 先找供应链公司 → 通过演示站点、ICO 或特征文件，定位大量使用该系统的高校目标；一旦测出该系统漏洞，即可"通杀"。
2. 先找高校目标 → 通过高校系统信息、ICO 等定位其供应链，再从供应链找到使用同一系统的其他高校目标，测出漏洞后同样"通杀"。

**核心思路：**
1. 尽量获取源码（明确源码获取途径）
2. 旁路方法（以相似目标的脆弱点作为突破口）

**目标供应链获取方式：** 企业产权信息、应用提示等
**供应链信息收集：** ICO 拓展、演示站点、成功案例等

## 我的一些补充看法

这篇笔记整体思路是清晰的，属于信src/edusrc挖洞里比较经典的"资产扩展 + 供应链打点"套路，几个点可以补充一下：

1. **GitHub监控可以自动化**：手动搜索效率低，建议直接用笔记里提到的 gshark、Github-Monitor 这类工具做定时轮询 + 关键词规则库（公司域名、邮箱后缀、内部系统名等），配合 Webhook 推送到企业微信/Telegram，比人工刷新有效得多。也可以关注 GitHub 的 secret scanning / gitleaks 规则集思路，反向理解厂商是怎么防的。

2. **信息泄漏搜索可以扩展的语法**：
   - `filetype:log`、`filetype:sql`、`filetype:env`、`filetype:bak` 也是高价值后缀
   - FOFA / Hunter / Quake / ZoomEye 等网络空间测绘引擎可以用 icon hash（favicon MD5/mmh3）做供应链系统的批量指纹匹配，比单纯谷歌语法效率高很多，笔记里提到的"ICO拓展"其实就是指这个
   - 网盘泄漏可以补充 `site:pan.baidu.com`、`site:aliyundrive.com` 等网盘站内搜索思路，以及企业文库类站点（如某些政企爱用的公开FTP/OA附件下载链接）

3. **供应链打点的关联手段**：
   - 除了 ICO 特征，还可以用 HTML 特征（如版权信息、特定 JS 文件名/版本号、登录页 title）做批量匹配
   - 证书透明度日志（crt.sh）反查同一供应商给不同客户签发的证书，也是发现同源资产的常用途径
   - ICP 备案信息反查（天眼查/企查查类工具，非大陆源的话可以用 aiqicha 的境外镜像或直接查工商公开接口）可以理清企业股权和供应商关系链

4. **合规提醒**：这套思路本身是标准的授权测试/SRC挖洞方法论，但落地时务必确保目标在授权范围内（尤其供应链"通杀"打法很容易打到未授权的第三方客户资产上），edusrc/补天类平台对资产归属认定比较严格，建议实操前先核实资产归属再提交。

如果你需要，我可以再帮你把这个笔记扩展成一个更完整的"信息收集方法论"文档，比如加上子域名收集、C段扫描、APP端资产等模块。
