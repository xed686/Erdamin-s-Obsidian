#  PHP 弱类型比较漏洞笔记

PHP 的类型比较机制（尤其是 `==` 的隐式类型转换）是代码审计和 CTF Web 题中一个高频考点，核心思路都是：**利用语言/函数在比较不同类型数据时的"隐式转换"规则，构造出"看起来不同、却被判定为相等"的输入，从而绕过身份校验、Token 校验等逻辑判断**。

---

## 一、`==` 与 `===` 的本质区别

| 运算符   | 类型        | 行为                                        |
| ----- | --------- | ----------------------------------------- |
| `==`  | 弱比较（松散比较） | 若两值类型不同，PHP 解析器会先做**隐式类型转换**，转换为同一类型后再比较值 |
| `===` | 强比较（严格比较） | 类型和值必须同时相同才判定为 `true`                     |

**审计意义**：凡是看到关键校验逻辑（如 Token、密码哈希、签名）使用 `==` 而非 `===`，都应优先考虑是否存在类型混淆绕过的可能。

---

## 二、MD5 弱比较缺陷（"0e 魔术哈希"）

### 原理
当一个字符串格式形如 `0e1234...`（以 `0e` 开头，后面全为数字）时，PHP 在做**弱比较**时会把它解析为"科学计数法表示的浮点数"（即 `0 × 10^1234...= 0`）。如果两个 MD5 值恰好都是这种格式，`md5($a) == md5($b)` 就会被判定为 `true`，即便 `$a != $b`。

### 典型漏洞代码
```php
if ($_GET['a'] != $_GET['b'] && md5($_GET['a']) == md5($_GET['b'])) {
    echo "Flag";
}
```

### 常见"0e 魔术哈希"对照表

| 原始字符串 | MD5 值 |
|---|---|
| `QNKCDZO` | `0e830400451993494058024219903391` |
| `240610708` | `0e462097431906509019562988736854` |
| `s878926199a` | `0e545993274517709034328855841020` |
| `s155964671a` | `0e342768416822451524974117254469` |
| `s214587387a` | `0e848240448830537924465865611904` |
| `s1091221200a` | `0e940624217856561557816327384675` |
| `s1885207154a` | `0e509367213418206700842008763514` |

> 审计/防御建议：涉及哈希比较的场景一律使用 `===`，或使用 `hash_equals()` 做比较（同时还能防时序攻击）。

## 三、`strcmp()` 类型比较缺陷

### 原理
`strcmp()` 设计用于比较**字符串**类型。在部分低版本 PHP 中，若强行传入**数组**等非字符串类型参数，函数内部处理异常，会直接返回 `0`（代表"相等"）而不是报错中断。若校验逻辑恰好以 `strcmp(...) == 0` 作为判断条件，攻击者只需将参数以数组形式传入（如 `password[]=1`），即可让 `strcmp()` 返回 `0` 从而绕过校验。

### 典型漏洞代码
```php
if (strcmp($_POST['password'], $real_password) == 0) {
    echo "Login Success";
}
// 传参方式：password[]=anything
```

> 新版本 PHP 中传入数组会抛出 `TypeError`，该缺陷主要存在于旧版本/未做异常捕获的代码中，审计价值随 PHP 版本升级逐渐降低，但仍常见于遗留系统。

---

## 四、Bool 类型比较缺陷

### 原理
使用 `json_decode()` 或 `unserialize()` 解析用户可控数据时，若输入内容无法正确解析为预期的数组/对象结构，PHP 可能将结果隐式处理为 `bool` 类型（如 `false`），而不是开发者预期的 `null` 或抛出异常。如果后续代码直接对该返回值做宽松判断（如 `if ($data['key'])`），就可能产生超出预期的逻辑分支，被用来绕过校验或触发报错回显等。

**审计意义**：对 `json_decode()` / `unserialize()` 的返回值，应始终显式校验类型（如 `is_array()`）后再使用，不要依赖隐式真假值判断。

---

## 五、`switch` 类型比较缺陷

### 原理
`switch` 语句在匹配 `case` 为数字的分支时，内部会将传入变量**强制转换为 int 类型**后再比较。这意味着像 `"1abc"`、`"1 "` 这样的字符串，在 `switch` 中可能被当作整数 `1` 处理，从而命中并非预期的 `case` 分支。

### 典型漏洞代码
```php
switch ($_GET['num']) {
    case 1:
        echo "匹配到 1";
        break;
    // 传入 num=1abc 同样会命中这个分支
}
```

---

## 六、`in_array()` / `array_search()` 数组比较缺陷

### 原理
`in_array($needle, $haystack, $strict)` 和 `array_search()` 的第三个参数 `$strict` 默认是 `false`，即**默认使用松散比较**。若数组中存在数字类型元素，用字符串去匹配时可能触发类型转换，导致本不应该匹配的值被判定为"存在于数组中"。

### 典型漏洞代码
```php
$whitelist = [0, 1, 2];
if (in_array($_GET['id'], $whitelist)) {  // 未指定 strict=true
    echo "通过白名单校验";
}
// 传入 id=abc 时，PHP 弱比较下 "abc" == 0 为 true，可能意外通过
```

> 防御建议：始终显式传入第三个参数 `true` 启用严格比较：`in_array($needle, $haystack, true)`。

---

## 七、`===` 数组比较绕过（MD5 数组报错特性）

### 原理
即使代码使用了严格比较 `===`，依然可能存在绕过空间。例如 `md5()` 函数若接收到**数组**类型参数，会直接报错并返回 `NULL`（而不是抛出致命错误中断脚本，视 PHP 版本而定）。如果校验逻辑是 `md5($a) === md5($b)`，只要让 `$a` 和 `$b` 都以数组形式传入，两边 `md5()` 的返回值都会变成 `NULL`，`NULL === NULL` 判定为真，从而绕过本应严格的校验。

### 典型漏洞代码
```php
if (md5($_GET['a']) === md5($_GET['b'])) {
    echo "Flag";
}
// 传参方式：a[]=1&b[]=2，两边 md5() 均返回 NULL
```

## 八、速查总结表

| 场景 | 缺陷函数/语法 | 利用思路 |
|---|---|---|
| 1 | `==` | 隐式类型转换导致不同值被判定相等 |
| 2 | `md5() ==` | 构造 `0e` 开头全数字哈希碰撞（"0e 魔术哈希"） |
| 3 | `strcmp() == 0` | 传入数组参数触发异常返回值 `0` |
| 4 | `json_decode()` / `unserialize()` | 解析失败隐式转为 bool，绕过后续宽松判断 |
| 5 | `switch` 数字 case | 字符串被强制转 int 命中非预期分支 |
| 6 | `in_array()` / `array_search()` 默认模式 | 未开启 `strict` 时的松散比较绕过白名单 |
| 7 | `md5() ===` | 两边均传数组，`md5()` 报错返回 `NULL`，`NULL === NULL` |

**统一防御原则**：
- 优先使用 `===` 做严格比较，而不是 `==`。
- 哈希值比较使用 `hash_equals()`。
- 数组查找显式开启 `strict` 参数。
- 对反序列化/JSON 解析结果做显式类型校验（`is_array()` 等），不依赖隐式真假判断。
- 对用户输入做类型强制转换或白名单校验，避免将原始用户输入直接传入敏感比较函数。
