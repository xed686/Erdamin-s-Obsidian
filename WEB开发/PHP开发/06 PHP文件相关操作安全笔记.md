# PHP 文件操作安全笔记（上传/遍历/下载/删除/读取/包含）

文件操作类功能（上传、下载、删除、浏览、包含等）几乎是每个 Web 应用的标配，也是代码审计中**漏洞密度最高**的功能点之一。核心审计思路始终是同一条：**凡是文件路径/文件名存在用户可控成分，且服务端未做严格校验，就存在被遍历/篡改/逃逸出预期目录的风险。**

---

## 一、文件上传

### 核心机制
`$_FILES` 是 PHP 预定义的超全局变量，用于在上传文件时从客户端接收文件并保存到服务器。它是一个包含上传文件信息的数组。

| 字段                           | 说明            |
| ---------------------------- | ------------- |
| `$_FILES["表单值"]["name"]`     | 上传文件的原始名称     |
| `$_FILES["表单值"]["type"]`     | 上传文件的 MIME 类型 |
| `$_FILES["表单值"]["size"]`     | 上传文件的字节大小     |
| `$_FILES["表单值"]["tmp_name"]` | 上传后的临时副本文件名   |
| `$_FILES["表单值"]["error"]`    | 上传过程中的错误代码    |

**关键函数**：`move_uploaded_file()` —— 将上传的临时文件移动到最终存储位置的函数。

### 审计要点
- `name`、`type` 均为**客户端提交的数据**，完全可被伪造，不能作为后缀/类型校验的唯一依据。
- 校验逻辑应结合：服务端 MIME 检测（而非信任 `$_FILES[...]["type"]`）、文件头魔术字节校验、白名单后缀校验（而非黑名单）、上传目录禁止解析脚本（Web 容器配置层面）等多重手段。
- `move_uploaded_file()` 的目标路径若拼接了用户可控内容（如自定义保存文件名/目录），还需额外防范路径穿越（见下文"文件遍历"部分）。

## 二、文件显示 / 目录遍历

### 基本流程
1. 打开目录，读取文件列表。
2. 递归循环遍历，逐层读取子目录内容。
3. 判断每一项是文件还是文件夹，分别处理。
4. 结合 `php.ini` 中的目录访问控制限制实际可读范围。

### 核心函数

| 函数 | 作用 |
|---|---|
| `is_dir()` | 检查指定路径是否为目录 |
| `opendir()` | 打开指定目录，返回句柄 |
| `readdir()` | 从句柄中逐个读取目录中的文件/子目录 |
| `scandir()` | 直接返回指定目录下文件和目录列表（数组形式），一次性获取 |

### 访问控制配置

| 配置 | 作用 |
|---|---|
| `open_basedir`（php.ini） | 限制 PHP 脚本可访问的目录范围 |
| `ini_set('open_basedir', __DIR__);` | 在代码中动态设置，限制脚本只能访问当前目录 |

### 审计要点
- 若目录遍历功能的"起始路径"或"子目录名"由用户参数拼接而成，且未校验 `../` 等路径穿越字符，攻击者可逃逸出预期目录，读取到任意位置的文件/目录结构（**目录遍历 / 任意文件列举漏洞**）。
- `open_basedir` 是服务端层面的兜底防护，但不能替代代码层面对用户输入路径的规范化校验（如 `realpath()` 校验 + 白名单根目录前缀比对）。

## 三、文件删除

| 方式 | 说明 |
|---|---|
| `unlink()` | PHP 内置的文件删除函数 |
| 调用系统命令 | `system()`、`shell_exec()`、`exec()` 等函数间接执行删除命令 |

### 审计要点
- 若待删除文件路径由用户参数控制且未做校验，可被用于**任意文件删除**（如删除日志、配置文件甚至关键业务文件造成拒绝服务）。
- 通过 `system`/`shell_exec`/`exec` 等函数拼接用户输入执行删除命令时，还需同时警惕**命令注入**风险（用户输入中若含 `;`、`|`、`` ` `` 等特殊字符未过滤，可能被用来拼接额外命令）。

## 四、文件下载

### 实现方式
通过修改 HTTP 响应头，让浏览器将响应内容识别为"附件下载"而非直接渲染展示：

```php
header("Content-Type: application/octet-stream");
header("Content-Disposition: attachment; filename=\"" . $file . "\"");
header("Content-Length: " . filesize($file));
readfile($file);
```

### 审计要点
- 这是**任意文件下载漏洞**最典型的代码形态：若 `$file` 变量直接由用户请求参数拼接而来，且未做路径规范化/白名单校验，攻击者可通过 `../../../etc/passwd` 等路径穿越方式下载任意服务器文件（包括源码、配置文件、密钥等敏感信息）。
- 防御思路：对传入文件名做白名单校验（仅允许指定目录下的指定文件/后缀），或使用文件 ID 映射真实路径而非直接拼接用户输入路径。

## 五、文件读取

| 方式 | 说明 |
|---|---|
| `file_get_contents()` | 一次性读取整个文件内容并返回字符串 |
| `fopen()` + `fread()` | 先打开文件句柄，再按需读取内容（适合大文件分段读取） |

### 审计要点
- 与文件下载漏洞原理一致，只是展现形式是直接将内容回显在页面而非触发浏览器下载，同样需要警惕路径穿越导致的任意文件读取。

## 六、文件包含

| 语句 | 说明 |
|---|---|
| `include` | 包含并运行指定文件，出错仅产生警告，脚本继续执行 |
| `require` | 包含并运行指定文件，出错产生致命错误，脚本终止 |
| `include_once` | 同 `include`，但同一文件只会被包含一次 |
| `require_once` | 同 `require`，但同一文件只会被包含一次 |

### 审计要点
- 这是风险等级最高的一类文件操作：若被包含的文件路径由用户输入控制，攻击者不仅能读取任意文件内容（本地文件包含 LFI），在特定条件下（如配合文件上传写入恶意内容、PHP 伪协议、日志投毒等）还可能进一步实现**远程代码执行（RCE）**。
- 常见利用手法包括：路径穿越读取敏感文件、`php://filter` 伪协议读取源码、`data://`/`php://input` 等伪协议配合执行代码、结合文件上传/日志文件写入 Webshell 后再包含触发。
- 防御核心：**包含路径绝不应由用户输入直接或间接拼接决定**，如确需动态包含，应使用白名单映射（如固定的模块名 → 固定文件路径的映射表）而非拼接原始输入。

## 七、速查总结表

| 功能 | 关键函数 | 典型漏洞 | 核心防御 |
|---|---|---|---|
| 上传 | `move_uploaded_file()` | 任意文件上传（Webshell） | 服务端 MIME/魔术字节校验、白名单后缀、上传目录禁解析 |
| 遍历 | `opendir()`/`readdir()`/`scandir()` | 目录遍历 | `open_basedir` + 路径规范化校验 |
| 删除 | `unlink()`/`system()`等 | 任意文件删除、命令注入 | 路径白名单、避免拼接命令执行删除 |
| 下载 | `readfile()` + 响应头 | 任意文件下载 | 文件名白名单/ID 映射，禁止直接拼接路径 |
| 读取 | `file_get_contents()`/`fopen()` | 任意文件读取 | 同下载 |
| 包含 | `include`/`require` 等 | 本地文件包含（LFI）→ 可能 RCE | 禁止用户输入直接决定包含路径，使用白名单映射 |
