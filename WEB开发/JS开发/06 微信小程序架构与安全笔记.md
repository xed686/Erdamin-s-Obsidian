# 微信小程序架构、开发与安全笔记

## 一、小程序创建

1. 下载微信开发者工具：https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html
2. 用开发者工具创建小程序项目模板（内置多种模板可直接引用练手）。

## 二、小程序架构

### 1. 主体结构（App 级别）

小程序包含一个描述**整体程序**的 `app`，和多个描述**各自页面**的 `page`。

小程序的主体部分（即 `app`）由三个文件组成，必须放在项目根目录：

| 文件 | 必需 | 作用 |
|---|---|---|
| `app.js` | 是 | 小程序逻辑 |
| `app.json` | 是 | 小程序公共配置 |
| `app.wxss` | 否 | 小程序公共样式表 |

### 2. 页面结构（Page 级别）

一个小程序页面由四个文件组成：

| 文件 | 作用 |
|---|---|
| `xxx.js` | 页面逻辑 |
| `xxx.json` | 页面配置 |
| `xxx.wxml` | 页面结构（类似 HTML） |
| `xxx.wxss` | 页面样式（类似 CSS） |

### 3. 项目整体目录结构

```
项目根目录/
├── pages/                  页面文件夹
│   ├── index/              首页
│   └── logs/                日志
├── utils/
│   └── util.js             工具类（mina 框架自动生成，也可自建 api/ 目录）
├── app.js                   入口 js（类似 Java 的 main 方法），全局逻辑
├── app.json                 全局配置文件
├── app.wxss                 全局样式文件
├── project.config.json      开发者工具"详情"中勾选的项目配置
└── sitemap.json             配置小程序及页面是否允许被微信搜索索引
```

> 审计意义：拿到一份小程序源码后，首先定位 `app.json`（能看到全部页面路径列表，相当于拿到了整个应用的"路由地图"）和各页面的 `.js` 文件（业务逻辑和接口调用都写在这里），这是信息收集阶段最高效的两个切入点。

## 三、小程序开发方式

| 方式 | 说明 |
|---|---|
| 可视化开发 | 在微信开发者工具中直接编写、预览 |
| 真机调试 | 扫码在真实手机设备上联调测试 |
| 编译预览 | 开发者工具内生成预览二维码 |
| NPM 编译 | 支持引入 npm 第三方包并在小程序环境中编译使用 |

### 两个值得关注的嵌套场景

**案例 1：嵌套 Web 应用资产**
```html
<web-view src="http://www.xiaodi8.com"></web-view>
```
小程序提供了 `web-view` 组件，可以直接在小程序页面内嵌入一个完整的网页（Web 应用）。

> **安全意义**：`web-view` 本质是把一个独立的 Web 资产嵌到了小程序外壳里。审计时要意识到：**小程序本身没问题，不代表嵌入的这个 Web 页面没问题**——需要把这个被嵌入的 URL 当作一个独立的 Web 渗透目标来对待，该走的 Web 漏洞排查流程（SQL 注入、XSS、SSRF 等）一样都不能少。这也是小程序资产测绘中"发现更多 Web 资产"的典型来源之一。

**案例 2：嵌套第三方云服务**
例如阿里云 OSS 对象存储的 AK/SK（AccessKey ID / AccessKey Secret）。

> **安全意义**：很多小程序为了方便直接上传文件到云存储，会在前端（小程序端）代码中**硬编码云服务的 AK/SK 密钥**。这类密钥一旦泄露，攻击者可以直接拿着密钥操作对应的云存储空间（读取、上传、删除、甚至遍历整个 Bucket 中其他用户的文件），危害等级很高，是小程序审计中"发现敏感信息"环节的重点目标。

## 四、小程序安全（核心审计方向）

### 1. 逆向反编译

微信小程序的前端代码（`.wxapkg` 包）本质上也是可以被还原的——小程序包下载下来后是经过打包/加密处理的二进制文件，需要通过专门工具解包，还原出原始的 `.js`/`.wxml`/`.wxss`/`.json` 等源文件结构，才能进行后续代码审计。

### 2. 敏感信息泄露

反编译还原出源码后，审计重点与此前《JavaScript安全分析与Ajax技术笔记》中"发现敏感信息"的思路完全一致，只是载体从网页 JS 换成了小程序代码：
- 硬编码的账号密码、测试账号
- API 密钥、AK/SK（对应上文"嵌套第三方云服务"案例）
- 代码注释中遗留的开发调试信息

### 3. 资产信息提取

从反编译后的代码中提取：
- 后端接口 IP 地址、域名
- 关联的 Web 应用地址（结合 `web-view` 嵌入场景）
- 未公开的测试环境/后台地址

这些信息可以进一步扩大渗透测试的资产范围，是小程序测试里"由点到面"的关键一步。

### 4. 代码逻辑安全

还原源码后分析具体业务逻辑：
- 加密/签名算法的实现方式（是否可在客户端被还原重放）
- 各类提交接口的参数构造逻辑、校验规则
- 与此前《前端加密与代码混淆笔记》中"断点调试还原明文"的审计思路可以直接套用——只是调试环境从浏览器 DevTools 换成了小程序开发者工具 / 反编译后的代码阅读。

## 六、总结

1. 小程序审计的整体思路和普通 Web 前端审计高度一致，只是"反编译还原源码"这一步是小程序特有的前置环节——拿到源码之前的工作重点是工具使用，拿到源码之后的审计重点（敏感信息、危险代码、逻辑校验、资产信息）和此前整理的 JS 安全审计思路完全通用。
2. `web-view` 嵌入的 Web 资产和硬编码的第三方云服务密钥（AK/SK）是小程序特有的两个高价值信息源，应作为信息收集阶段的固定检查项。
3. 多款反编译工具可以配合使用，优先用一个工具快速拿到源码结构，再按常规前端代码审计流程推进。
