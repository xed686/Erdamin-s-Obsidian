# NodeJS 环境搭建、功能实现与安全笔记

## 一、Node.js 是什么

**官方定义**：Node.js 是一个开源的、跨平台的 JavaScript 运行环境。

**通俗理解**：Node.js 本质就是**一款应用程序/软件**，它的作用是让 JavaScript 脱离浏览器，也能在服务器端被执行。

### 前端技术栈演进脉络
```
HTML + CSS → JavaScript → Node.js → Webpack → React / Vue → 小程序
```
Node.js 是整条前端技术演进链路的"地基"之一——有了它，JS 才能脱离浏览器跑在服务端，后续的 Webpack（打包构建）、React/Vue（前端框架）、小程序等生态都依赖于 Node.js 提供的运行环境与包管理体系（npm）。

---

## 二、为什么要用 Node.js？什么时候会用到它？

### 1. 为什么要用

在 Node.js 出现之前，前端（浏览器里跑的 JS）和后端（处理数据库、文件、业务逻辑的服务端代码）是**两套完全不同的语言体系**——比如前端写 JS，后端写 PHP/Java/Python。Node.js 的核心价值在于：**让 JavaScript 既能跑在浏览器里，也能跑在服务器上**，由此带来几个实际好处：

| 价值点 | 说明 |
|---|---|
| 前后端语言统一 | 一个开发者可以用同一门语言（JS）同时写前端页面逻辑和后端接口逻辑，不需要切换语言思维，团队协作和代码复用成本也更低 |
| 异步非阻塞、适合高并发 | Node.js 基于事件驱动、单线程异步 I/O 模型，在处理大量"短连接、高并发"的请求（如实时聊天、API 接口转发）时效率很高，不会因为一个请求卡住而阻塞其他请求 |
| 生态庞大（npm） | npm 是全球最大的包管理生态之一，几乎任何常见功能（上传、加密、数据库连接等）都有现成的三方库可以直接 `npm i` 安装使用，开发效率高 |
| 轻量级服务端/中间层 | 相比传统重量级后端框架，Node.js 启动快、资源占用相对小，很适合做"中间层"服务（比如接口聚合、反向代理、BFF 层） |

### 2. 什么场景会用到它

| 场景 | 说明 |
|---|---|
| 做前端工程化工具链 | Webpack、Vite、React/Vue 的开发环境、各类脚手架（CLI 工具），底层都依赖 Node.js 运行 |
| 做实时应用的后端 | 聊天室、消息推送、协同编辑等需要长连接、高并发、低延迟的场景，Node.js 是常见选型（配合 WebSocket） |
| 做接口聚合/中间层（BFF） | 前端需要调用多个后端微服务时，用 Node.js 写一层"中间服务"，统一聚合、裁剪数据再返回给前端，减少前端直接对接多个后端的复杂度 |
| 做轻量级 API 服务/管理后台 | 配合 Express 等框架，快速搭建一个小型的 Web 服务或管理系统后台（也是你前面环境搭建练习的场景） |
| 做命令行工具/自动化脚本 | 很多开发工具、自动化构建脚本、CLI 命令行程序都是用 Node.js 写的 |

### 3. 从渗透测试视角理解"什么时候会遇到它"

对你的审计/渗透场景来说，判断"目标用没用 Node.js"本身就是信息收集的一环——常见识别线索包括：响应头里出现 `X-Powered-By: Express`、报错信息里出现 `node_modules` 路径或 `TypeError`/`ReferenceError` 等 JS 风格的报错堆栈、接口返回的 JSON 结构风格、`package.json`/`.js` 后缀文件意外可访问等。一旦识别出目标是 Node.js 技术栈，审计重点就会从"PHP 那套函数清单"切换到本文第五节的 **SQL 注入/文件操作/RCE/原型链污染**这几类更贴合 Node.js 生态的漏洞类型上。

## 三、环境搭建

### 1. 参考文档
- 教程：https://www.runoob.com/nodejs/nodejs-tutorial.html
- 官网安装包：https://nodejs.org/en

### 2. 常用三方库

| 库 | 作用 |
|---|---|
| `express` | 简洁而灵活的 Node.js Web 应用框架，是 Node.js 做 Web 开发最常用的基础框架 |
| `body-parser` | Node.js 中间件，用于解析 JSON、Raw、Text 和 URL 编码的请求数据 |
| `cookie-parser` | 解析 Cookie 的工具，通过 `req.cookies` 即可取到请求携带的 cookie 并转成对象 |
| `multer` | Node.js 中间件，用于处理 `enctype="multipart/form-data"` 的表单数据（文件上传场景） |
| `mysql` | Node.js 连接 MySQL 的专用库，用于对数据库进行操作 |

### 3. 安装命令
```bash
npm i express
npm i body-parser
npm i cookie-parser
npm i multer
npm i mysql
```

## 五、NodeJS 安全要点

### 1. 常见漏洞类型
- **SQL 注入 & 文件操作类漏洞**：与 PHP 审计思路一致，核心看用户输入是否被拼接进 SQL 语句/文件路径。
- **RCE（远程代码执行）& 原型链污染**：Node.js 生态下较有特色的两类高危漏洞。

### 2. 实战测试思路：黑盒 vs 白盒

| 方式 | 思路 |
|---|---|
| 判断阶段 | 参考前期信息收集结果（识别出目标使用了 Node.js、具体框架、版本等） |
| **黑盒测试** | 对目标的各类功能点和参数进行 payload 测试，通过响应差异判断是否存在漏洞（无法看到源码的情况下使用） |
| **白盒测试** | 直接拿到源码，对代码中的具体写法进行审计分析，定位危险函数调用和数据流 |

### 3. 原型链污染（Prototype Pollution）—— Node.js/JS 特有的高危漏洞

**原理**：JavaScript 中几乎所有对象都通过 `__proto__` 属性关联到自己的原型对象。**如果攻击者能够控制并修改某个对象的原型（`__proto__`），那么这个修改会影响所有与该对象同属一个类、或源自同一父类/祖先类的其他对象**——因为它们共享同一条原型链。

**危害延伸**：原型链污染本身不直接等于代码执行，但如果应用后续代码逻辑中存在"从对象属性里取值并执行"的操作（比如动态读取某个配置属性去调用函数），攻击者污染后的属性值就可能被后续逻辑直接使用，从而间接导致权限绕过、逻辑绕过甚至代码执行。

**常见产生场景**：对象合并/深拷贝函数（如早期部分库的 `merge()`、`extend()`、`_.merge()` 等）在递归处理用户可控的 JSON 数据时，没有对 `__proto__`、`constructor.prototype` 等特殊键名做过滤，使得用户传入的 JSON 中若包含 `{"__proto__": {...}}` 这类键，就能直接污染到全局原型对象。

## 七、总结

1. Node.js 本身只是"让 JS 能跑在服务端"的运行环境，安全问题的根源和 PHP 一样——都是"用户可控输入未经校验直接流入了危险操作"，只是语言生态不同、函数名不同（如 `eval`/`exec` 对应 PHP 的 `eval`/`system` 系列）。
2. 原型链污染是 Node.js/JS 生态里相对独特的一类漏洞，审计 Node.js 项目时应额外关注对象合并/深拷贝相关代码是否对 `__proto__` 等特殊键做了过滤，这是 PHP 审计体系里没有的知识点，需要单独建立敏感度。
3. 测试路径上，先判断目标技术栈（黑盒信息收集），再决定走黑盒 payload 测试还是白盒代码审计，两者可以结合使用：黑盒先定位可疑功能点，再尝试找到对应源码做精确审计。
