# 网安视角：把一个网站系统想象成一栋餐厅大楼

> 本笔记以"餐厅大楼"为核心比喻，从零梳理一个网站系统的完整架构，
> 说明各组成部分与 Linux 目录之间的关系，并以渗透测试者（小偷）视角
> 讲解每个区域的利用方式与原理。

---

## 一、大楼的层次结构：这栋餐厅是怎么搭起来的

一个网站系统不是只有 HTML 和 JS，它是一栋**分层运转的大楼**，从地基到装修一共四层：

```
┌─────────────────────────────────────────┐
│     前端（HTML / CSS / JS）              │  ← 顾客看到的门面装修
├─────────────────────────────────────────┤
│  Web服务器软件（Nginx / Apache）         │  ← 前台接待员
├─────────────────────────────────────────┤
│  后端程序（PHP / Python / Node.js）      │  ← 后厨厨师
│  数据库（MySQL / PostgreSQL）            │  ← 地下档案室
├─────────────────────────────────────────┤
│         Linux 操作系统                   │  ← 大楼的水电消防系统
├─────────────────────────────────────────┤
│         服务器硬件                       │  ← 大楼的钢筋混凝土框架
└─────────────────────────────────────────┘
```

| 层级 | 餐厅类比 | 具体例子 | 说明 |
|---|---|---|---|
| 服务器硬件 | 钢筋混凝土框架 | 阿里云/AWS 云主机 | 物理层，真实存在的 CPU、内存、硬盘 |
| Linux 操作系统 | 大楼的水电消防系统 | Ubuntu / CentOS / Debian | 装在硬件上，让所有软件有地方运行 |
| Web服务器软件 | 前台接待员 | Nginx、Apache | 接收外部请求，决定转给谁处理 |
| 后端程序语言 | 后厨厨师 | PHP、Python、Node.js | 处理业务逻辑（验证密码、生成内容） |
| 数据库 | 地下档案室 | MySQL、PostgreSQL | 存放所有结构化数据（用户、订单等） |
| 前端 | 门面装修 | HTML、CSS、JS | 在**用户自己的浏览器**里运行，不在服务器上 |

> **关键认知**：服务器是"大楼框架"，Linux 是"让大楼能用的水电系统"。
> 没有 Linux，Nginx、PHP、MySQL 这些软件都没有地方跑。
> 前端的 HTML/CSS/JS 运行在**用户自己的电脑**上，不在服务器上。

## 二、大楼各区域详解

### 🪟 前厅门面（前端）—— HTML / CSS / JS

这是**顾客走进餐厅第一眼看到的东西**：装修风格、菜单排版、服务员的即时反应。

- **HTML** = 桌椅摆放、菜单文字（内容结构）
- **CSS** = 装修配色、灯光风格（样式）
- **JS** = 服务员的即时反应，比如按呼叫铃灯会亮（网页交互）

浏览器"查看源代码"能看到的就是这部分，因为它被**完整下载到了你本地电脑**。这也是为什么 XSS 漏洞能生效——你在前厅的菜单栏上偷偷刻了一段"恶意文字"，下一个来看菜单的顾客就会中招，而不是影响后厨。

---

### 🧑‍💼 前台接待员（Web服务器软件）—— Nginx / Apache

#### 它是什么

Nginx 和 Apache **不是"有请求才启动"的程序**，而是一个**随服务器开机就一直在后台运行的服务**，就像前台接待员**全天候在岗**，不管有没有客人来都站在门口等。

它监听着服务器的网络端口（通常是 80 端口/HTTP 或 443 端口/HTTPS），只要有浏览器发来请求，立刻响应处理。

```bash
systemctl status nginx    # 查看接待员是否在岗、已在岗多久
```

#### 它和 /var/www 的关系

`/var/www` **不是 Nginx 自带的**，而是 Nginx 的"工作手册"（配置文件）里写着"去这里取菜"。

配置文件 `/etc/nginx/nginx.conf` 里有这样一行：

```nginx
server {
    listen 80;
    root /var/www/html;      # 👈 工作手册：去这个货架取文件
    index index.html index.php;
}
```

Nginx 本身不知道 `/var/www` 的存在，是**配置文件告诉它**"你负责的货架在这里"。如果管理员把这行改成 `/home/website`，Nginx 就去那里取，`/var/www` 对它而言不复存在。

#### 两种请求的处理方式

**静态请求**（纯 HTML/图片，不需要计算）：

```
浏览器 → Nginx → 直接去 /var/www/html/ 取文件 → 返回给浏览器
```
Nginx 自己就处理完了，不需要 PHP 或数据库介入，就像客人问"有没有菜单"，接待员直接从旁边架子拿一份递过去。

**动态请求**（登录、查询、提交数据）：

```
浏览器 → Nginx → 转交给 PHP 解释器 → PHP 读取 /var/www/html/login.php 并执行
→ PHP 查询 MySQL → 数据库返回结果 → PHP 生成 HTML → 经 Nginx 返回浏览器
```
Nginx 自己**不执行 PHP 代码**，它只是"传话人"，把请求转给 PHP，再把结果端回来。

#### 🔴 小偷视角

| 攻击点 | 原理 | 利用方式 |
|---|---|---|
| **配置错误（目录遍历）** | Nginx 配置不当，导致可以访问 `/var/www` 以外的目录 | 直接读取服务器上的敏感文件 |
| **文件上传漏洞** | 上传目录没禁止执行 PHP，把 `shell.php` 传到 `/var/www/html/uploads/` | 通过浏览器访问该文件，触发 PHP 执行，拿到 webshell |
| **信息泄露** | Nginx 报错页面暴露版本号、路径信息 | 定向查找该版本的已知 CVE 漏洞 |
| **`.git` 残留** | 开发者把代码直接部署时忘了删 `/var/www/html/.git/` | 下载整个源码历史，找旧版本中的硬编码密码 |

---

### 🍳 后厨厨师（后端程序）—— PHP / Python / Node.js

接待员（Nginx）把动态请求转来之后，PHP/Python 负责**真正处理业务逻辑**：验证密码、计算价格、生成个性化内容。

它的代码文件就存放在 `/var/www/html/` 里（和 HTML 文件放在一起），但它不是"被展示"的，而是"被执行"的。这个区别在渗透里至关重要：

- 访问 `/var/www/html/index.html` → Nginx 把文件内容**原样**发给你
- 访问 `/var/www/html/login.php` → Nginx 把这个文件交给 PHP **执行**，你收到的是执行结果

#### 🔴 小偷视角

| 攻击点 | 原理 | 利用方式 |
|---|---|---|
| **SQL 注入** | PHP 代码把用户输入拼接进了 SQL 查询，没有过滤 | 构造恶意输入绕过验证，直接查数据库任意数据 |
| **文件包含漏洞（LFI）** | PHP 的 `include()` 函数直接用用户输入的参数 | 让服务器"包含"并执行 `/etc/passwd` 等敏感文件 |
| **命令执行漏洞（RCE）** | PHP 代码把用户输入直接传给系统命令函数如 `exec()` | 注入系统命令，直接在服务器上执行任意操作 |
| **硬编码凭证** | 开发者把数据库密码直接写在代码里，如 `wp-config.php`、`.env` | 读取这些文件获取数据库账号密码，进一步渗透 |

---

### 🗄️ 地下档案室（数据库）—— MySQL + /var/lib/mysql/

#### 它是什么

MySQL 和 Nginx 性质完全一样——**也是一个一直在后台运行的服务**，随开机启动，一直等着 PHP 来查询。它把所有数据以文件形式存在 Linux 的目录里：

```
/var/lib/mysql/          ← 数据库的真实数据文件存放位置（相当于档案室的货架）
    ├── mysql/           ← 系统级权限表
    ├── 网站数据库名/     ← 该网站的所有表文件
    │     ├── users.ibd  ← 用户表数据
    │     └── orders.ibd ← 订单表数据
    └── ...
```

#### 它为什么不对外开放

正常情况下数据库**只监听内网**（127.0.0.1:3306），外部网络根本无法直接连接——就像档案室在地下室，顾客根本不知道入口在哪：

```
外网用户 → 只能访问 → Nginx（80/443端口，对外）
                            ↓ 内部转交
                         PHP（在服务器内部）
                            ↓ 内部查询 127.0.0.1:3306
                         MySQL（只监听内网，顾客进不去）
```

#### 🔴 小偷视角

| 攻击点 | 原理 | 利用方式 |
|---|---|---|
| **3306 端口对外暴露** | 运维配置失误，数据库直接暴露公网 | 用 `nmap` 扫描发现，直接尝试弱口令登录数据库 |
| **SQL 注入打穿数据库** | 通过后端 PHP 的漏洞间接操控数据库 | 用 `sqlmap` 自动化跑，dump 全部用户数据、密码哈希 |
| **UDF 提权** | MySQL 允许加载自定义函数（User Defined Function） | 上传恶意 `.so` 文件到 `/var/lib/mysql/`，借 MySQL 的权限执行系统命令 |
| **读取数据文件** | 已有 root 权限后直接读 `/var/lib/mysql/` | 离线解析数据库文件，无需登录数据库即可拿数据 |

### 🗂️ 行政部文件柜（/etc）—— 配置文件总仓库

`/etc` 里全是**纯文本配置文件**，相当于行政部门那一整柜的"规章制度文档"——写着这栋大楼怎么运转、谁有什么权限、各部门的对接规则。没有可执行程序，只有文字，但**这些文字决定了整栋楼的运行规则**。

| 文件 | 类比 | 内容 | 🔴 小偷利用方式 |
|---|---|---|---|
| `/etc/passwd` | 员工花名册 | 所有系统账号、home目录、使用的shell | 枚举可攻击账号，判断哪些是服务账号、哪些可能有弱口令 |
| `/etc/shadow` | 密码保险柜 | 账号密码的哈希值（只有root能读） | 若能读到，拿去离线爆破（hashcat/john） |
| `/etc/sudoers` | 权限授权单 | 谁被允许用 root 权限做哪些事 | 找 `NOPASSWD` 配置，直接借 root 身份执行命令（提权核心线索） |
| `/etc/crontab`、`/etc/cron.d/` | 例行工作安排表 | 定时自动执行的任务脚本 | 若定时任务以 root 跑、且脚本文件小偷可写 → 篡改脚本内容实现提权/持久化 |
| `/etc/hosts` | 内部通讯簿 | 手动指定的域名-IP 映射 | 了解内网其他主机的存在，辅助横向移动画地图 |
| `/etc/nginx/nginx.conf` | 接待员工作手册 | Nginx 的所有配置 | 了解网站根目录在哪、有哪些子域名、有没有配置错误 |
| `/etc/mysql/my.cnf` | 档案室管理规定 | MySQL 配置，包括数据目录、监听地址 | 确认数据库数据存在哪里、是否监听外网 |
| `/etc/ssh/sshd_config` | 远程访问规则 | SSH 服务的配置 | 看是否允许 root 直接登录、是否允许密码登录（方便后续渗透路径规划） |

### 🏠 员工宿舍 vs 老板套房（/home、/root）

- **/home/用户名/**：每个员工的私人宿舍，里面的东西理论上只有自己能看。
- **/root/**：老板的顶层套间，门禁最严，普通员工根本进不去。

小偷能进自己账号对应的宿舍（比如 `/home/www-data`），但会重点翻里面几样东西：

| 文件 | 类比 | 🔴 小偷利用方式 |
|---|---|---|
| `~/.bash_history` | 员工随手记的备忘录 | 明文密码、内网 IP、执行过的敏感命令经常被不小心记录在这里 |
| `~/.ssh/id_rsa` | 枕头底下藏的万能钥匙(私钥) | 没有密码保护的私钥直接偷走，可冒充该用户 SSH 登录其他机器（横向移动） |
| `~/.ssh/authorized_keys` | 门锁的授权放行清单 | 若小偷对该文件有写权限，偷偷塞入自己的公钥 → 以后无需密码随时进出（持久化后门） |
| `/root/` 本身 | 老板套间 | 拿到 root 权限后进入，里面可能有密码文件、证书、私钥等最高价值数据 |

---

### 📹 监控录像室（/var/log）

存着整栋大楼所有的"监控录像"，记录谁几点几分从哪个门进来、干了什么、有没有触发报警。

| 日志文件 | 记录内容 |
|---|---|
| `/var/log/auth.log` | 所有登录行为，成功/失败的 SSH 记录 |
| `/var/log/syslog` | 系统级别的事件记录 |
| `/var/log/nginx/access.log` | Nginx 接待员的接客记录（哪个 IP 访问了哪个路径） |
| `/var/log/nginx/error.log` | 接待员遇到的错误（可能暴露路径信息）|
| `/var/log/mysql/error.log` | 数据库报错记录 |

#### 🔴 小偷视角（双刃剑）

- **顺查**：翻 `access.log` 可以看出网站的目录结构、有哪些接口、别的用户访问了什么路径，用来辅助后续攻击。
- **反取证**：小偷得手后回来清理自己的入侵痕迹，删除或篡改对应时间段的日志。
- **注意**：乱删日志本身就是很显眼的红旗，且有授权的众测/赏金项目通常明令禁止破坏日志完整性，这是职业操守问题。

---

### 📦 无人看管的临时储物间（/tmp、/dev/shm）

这两个目录的特点：
- **所有用户都能写**，不需要高权限
- 很多安全监控工具懒得盯着这里
- `/dev/shm` 是内存映射区域，读写速度极快，重启后清空

类比：大楼走廊尽头一个没人管的储物柜，随便什么人都能塞东西进去，保安不太查这里。

#### 🔴 小偷视角

| 操作 | 原理 |
|---|---|
| **落地攻击工具** | webshell 拿到执行权限后，第一步往往是把提权脚本、扫描工具下载到 `/tmp` 里临时存放 |
| **编译提权程序** | 把提权用的 C 代码上传到 `/tmp`，在服务器上用 `gcc` 编译成可执行文件 |
| **过渡反弹 shell** | 把反弹 shell 的脚本放在 `/tmp`，执行后建立稳定的交互式连接 |
| **利用 /dev/shm 规避检测** | 部分 EDR 工具不监控内存文件系统，在 `/dev/shm` 里的文件更隐蔽 |

---

### 📊 实时监控大屏（/proc）

`/proc` 是**虚拟目录**，里面的内容不存在硬盘上，是 Linux 内核**实时生成**的"数据看板"，反映系统当前运行状态。每个正在运行的进程都有一个以 PID 命名的子目录：

```
/proc/
  ├── 1/              ← PID 为 1 的进程（通常是 systemd）
  │   ├── cmdline     ← 这个进程启动时用的命令和参数
  │   ├── environ     ← 这个进程启动时的环境变量
  │   └── fd/         ← 这个进程打开了哪些文件
  ├── 1234/           ← PID 为 1234 的进程
  └── ...
```

#### 🔴 小偷视角

| 文件 | 利用方式 |
|---|---|
| `/proc/[PID]/environ` | 某些程序会把数据库密码、API 密钥作为环境变量传入，这里能**明文看到** |
| `/proc/[PID]/cmdline` | 看到某个进程启动时用的完整命令，可能包含路径、账号等敏感信息 |
| `/proc/[PID]/fd/` | 查看进程当前打开了哪些文件，辅助判断服务器在运行什么、数据存在哪 |
| `/proc/net/tcp` | 查看当前所有 TCP 连接，相当于在内部摸清楚哪些端口在监听，比 `netstat` 更难被 hook 绕过 |

---

### 🏷️ 散落各处的万能钥匙牌（SUID / SGID 文件）

这不是一个固定目录，而是**散落在大楼各处的一类特殊标记文件**，常见于 `/usr/bin`、`/bin`。

**SUID 是什么**：Linux 里每个文件有一个权限标记，正常程序谁运行就用谁的权限。但贴了 SUID 标签的程序，**不管谁运行它，都自动用文件所有者（通常是 root）的权限执行**。

类比：大楼里有一把扫帚，正常情况下服务员拿着扫帚就是"服务员在扫地"。但这把扫帚被贴了一张"持有者自动获得老板权限"的标签——任何人拿起这把扫帚都变成了老板。

系统里有一些**本来就该有** SUID 的程序（比如 `passwd` 命令需要以 root 权限修改 `/etc/shadow`）。但如果**本不该有 SUID 标签的程序被错误地设置了这个权限**，就是一个高危提权漏洞。

#### 🔴 小偷视角

```bash
# 扫描整个系统中有 SUID 标签的文件
find / -perm -u=s -type f 2>/dev/null
```

找到之后，去 **GTFOBins**（https://gtfobins.github.io）这个网站查——它专门收录了"哪些正常工具一旦被贴上 SUID 标签就能被利用提权"，比如 `find`、`vim`、`python`、`bash` 等常见命令。

配置错误的 SUID 程序往往是从"服务员"（低权限用户）直接跳到"老板"（root）的**最快捷径**。

## 三、完整攻击链：小偷是怎么一步步拿下这栋大楼的

```
【外部踩点】
目标网站 → nmap 扫描端口 → 发现 80/443 (Nginx) 和意外暴露的 3306 (MySQL)

【突破前台】
↓ 发现网站有文件上传功能（后端 PHP 代码写得有漏洞）
↓ 上传伪装成图片的 shell.php 到 /var/www/html/uploads/
↓ 浏览器访问 http://目标/uploads/shell.php
↓ Nginx 把请求转给 PHP 执行，PHP 执行了恶意代码

【拿到 webshell】（权限：www-data，低权限）
↓ 用 webshell 执行命令：下载反弹 shell 脚本到 /tmp/
↓ 执行脚本，建立稳定的交互式 shell 连接

【内部踩点】
↓ 翻 /var/www/html/ 里的配置文件 → 找到 wp-config.php 里的数据库密码
↓ 用密码连接 MySQL，dump 用户表拿到所有用户密码哈希
↓ 查 /etc/passwd → 枚举系统账号，发现有个账号叫 deploy
↓ 翻 /home/deploy/.bash_history → 发现里面有 SSH 私钥的使用记录
↓ 找到 /home/deploy/.ssh/id_rsa → 私钥没有密码保护

【横向移动】
↓ 用偷来的私钥 SSH 登录内网另一台服务器（数据库专用机）

【本地提权】（回到第一台机器）
↓ 查 /etc/sudoers → 发现 www-data 可以无密码执行 /usr/bin/find
↓ 查 GTFOBins 确认 find 有 SUID 提权用法
↓ 执行：sudo find . -exec /bin/bash \; → 拿到 root shell

【维持权限】
↓ 在 /root/.ssh/authorized_keys 里写入自己的公钥（持久化后门）
↓ 清理 /var/log/nginx/access.log 里自己的访问记录（反取证）
↓ 在 /etc/crontab 里写入定时反弹 shell 任务（更隐蔽的持久化）
```

## 四、大楼各区域速查表

| 区域 / 目录 | 大楼类比 | 组件关联 | 🔴 小偷核心操作 |
|---|---|---|---|
| `/var/www/html/` | 前台货架 | Nginx 取文件的地方 | 找 `.env`/`wp-config.php` 硬编码密码；植入 webshell；找 `.git` 泄露 |
| `/etc/nginx/nginx.conf` | 接待员工作手册 | Nginx 的配置文件 | 了解网站结构、根目录位置、是否有配置错误 |
| `/var/lib/mysql/` | 档案室货架 | MySQL 数据文件存放处 | root 权限后离线读取数据库文件；UDF 提权 |
| `/etc/mysql/my.cnf` | 档案室管理规定 | MySQL 的配置文件 | 确认数据库监听地址（是否对外暴露）、数据目录 |
| `/etc/passwd` | 员工花名册 | Linux 账号系统 | 枚举所有账号，定位攻击目标 |
| `/etc/shadow` | 密码保险柜 | Linux 账号系统 | 读取密码哈希，离线爆破（hashcat） |
| `/etc/sudoers` | 权限授权单 | Linux 权限系统 | 找 `NOPASSWD` 配置错误，直接借 root 权限执行命令 |
| `/etc/crontab`、`/etc/cron.d/` | 例行工作安排表 | Linux 定时任务 | 篡改 root 权限脚本，实现提权或持久化后门 |
| `/etc/hosts` | 内部通讯簿 | Linux 网络配置 | 发现内网其他主机，辅助横向移动 |
| `/etc/ssh/sshd_config` | 远程访问规则 | SSH 服务配置 | 判断是否允许 root 登录、密码登录，规划后续渗透路径 |
| `~/.bash_history` | 员工备忘录 | 用户 home 目录 | 捡漏明文密码、敏感命令、内网 IP |
| `~/.ssh/id_rsa` | 枕头底下的私钥 | 用户 home 目录 | 偷走后冒充该用户横向移动到其他机器 |
| `~/.ssh/authorized_keys` | 门锁放行清单 | 用户 home 目录 | 写入自己公钥，植入免密登录后门 |
| `/var/log/` | 监控录像室 | 系统/服务日志 | 倒查内部规律；得手后清理自己的入侵痕迹 |
| `/tmp/`、`/dev/shm/` | 无人看管的储物间 | Linux 临时目录 | 落地工具、编译提权程序、存放反弹 shell 脚本 |
| `/proc/[PID]/` | 实时监控大屏 | Linux 内核虚拟目录 | 从进程环境变量里捡密码；查内网 TCP 连接情况 |
| SUID 文件（散落各处） | 万能钥匙牌 | Linux 权限系统 | `find / -perm -u=s` 扫描，配合 GTFOBins 提权 |

## 五、一句话总结各层关系

> **服务器**（钢筋框架）装着 **Linux**（水电系统），
> Linux 上跑着 **Nginx**（接待员）、**PHP**（厨师）、**MySQL**（档案室）；
> Nginx 通过配置文件找到 **/var/www** 这个货架；
> MySQL 把所有数据存在 **/var/lib/mysql** 这个货架；
> 整栋大楼的规章制度全在 **/etc** 这个文件柜里；
> 小偷（渗透测试者）从前台的漏洞突破，进门之后靠熟悉大楼布局一步步拿到老板套间（root）的钥匙。
