## 一、本节在做什么

Agent 的核心是"大模型 + 循环代码 + 工具函数"。这一节先把三个零件做好：

```
HelloAgentsLLM   →  会"思考"的大脑：负责调用大模型
search 函数      →  一个具体的工具：负责联网搜索
ToolExecutor     →  工具箱：负责登记、查找、列出工具
测试代码          →  手工模拟一次"Action 调用"，验证零件能配合
```

**为什么先单独造零件、单独测试：** 如果一上来就整体组装，出了问题分不清是模型、解析、工具还是循环的毛病。每个零件先单独验证，出错时能很快缩小范围。

## 二、环境与配置

### 2.1 需要安装的包

```bash
pip install openai python-dotenv google-search-results
```

> `serpapi` 相关的包名容易混淆：教程使用的是 `google-search-results`（代码里 `from serpapi import SerpApiClient`）。装错了会导入失败，装之前对一下教程的写法。

### 2.2 `.env` 文件

在项目文件夹新建名为 `.env` 的文件，**值写在这里，代码里只写标签名**：

```env
OPENAI_API_KEY="你的模型服务密钥"
OPENAI_BASE_URL="https://aihubmix.com/v1"
MODEL_NAME="从模型中心复制的模型名"
SERPAPI_API_KEY="你的 SerpApi 密钥"
```

注意：

- 文件名就是 `.env`，不是 `.env.txt`。
- 等号两边不要有空格。
- `OPENAI_BASE_URL` 要写到 `/v1` 为止，且是小写 `v`。
- 想改超时时间，可以多加一行 `LLM_TIMEOUT=120`；不写则默认 60 秒。

### 2.3 `os.getenv()` 的正确用法

`.env` 像一排带标签的储物格：

```
MODEL_NAME      →  里面放着模型名
OPENAI_API_KEY  →  里面放着密钥
SERPAPI_API_KEY →  里面放着搜索服务的密钥
```

```python
os.getenv("MODEL_NAME")            # 正确：括号里是标签名，返回里面的值
os.getenv("qwen3.8-flash-free")    # 错误：把"值"当成了标签名，找不到，返回 None
os.getenv("LLM_TIMEOUT", 60)       # 第二个参数是默认值：找不到标签时用它
```

**口诀：括号里写标签名（`.env` 等号左边），值留在 `.env` 里。**

`load_dotenv()` 的作用是把 `.env` 里的内容读进环境变量，没有这一行，`os.getenv` 什么都读不到。

## 三、零件一：`HelloAgentsLLM`（调用大模型）

### 3.1 思路

把密钥、地址、流式输出这些细节封装进一个类里，上层代码只需要 `llm.think(messages)` 就能拿到回答。

### 3.2 代码

```python
import os
from openai import OpenAI
from dotenv import load_dotenv
from typing import List, Dict

load_dotenv()


class HelloAgentsLLM:
    """
    为本书 "Hello Agents" 定制的LLM客户端。
    它用于调用任何兼容OpenAI接口的服务，并默认使用流式响应。
    """

    def __init__(self, model: str = None, apiKey: str = None, baseUrl: str = None, timeout: int = None):
        """初始化客户端。优先使用传入参数，如果未提供，则从环境变量加载。"""
        self.model = model or os.getenv("MODEL_NAME")
        apiKey = apiKey or os.getenv("OPENAI_API_KEY")
        baseUrl = baseUrl or os.getenv("OPENAI_BASE_URL")
        timeout = timeout or int(os.getenv("LLM_TIMEOUT", 60))

        if not all([self.model, apiKey, baseUrl]):
            raise ValueError("模型ID、API密钥和服务地址必须被提供或在.env文件中定义。")

        self.client = OpenAI(api_key=apiKey, base_url=baseUrl, timeout=timeout)

    def think(self, messages: List[Dict[str, str]], temperature: float = 0) -> str:
        """调用大语言模型进行思考，并返回其响应。"""
        print(f"🧠 正在调用 {self.model} 模型...")
        try:
            response = self.client.chat.completions.create(
                model=self.model,
                messages=messages,
                temperature=temperature,
                stream=True,
            )

            print("✅ 大语言模型响应成功:")
            collected_content = []
            for chunk in response:
                if not chunk.choices:
                    continue
                content = chunk.choices[0].delta.content or ""
                print(content, end="", flush=True)
                collected_content.append(content)
            print()  # 流式输出结束后换行
            return "".join(collected_content)

        except Exception as e:
            print(f"❌ 调用LLM API时发生错误: {e}")
            return None
```

### 3.3 方法与语法含义

| 写法 | 含义 |
|---|---|
| `__init__` | Python 固定名字，创建对象时自动执行，用来做初始化 |
| `model or os.getenv(...)` | 传了参数就用传的，没传才去读环境变量（`or` 左边有值时不会算右边） |
| `self.model` | 存在对象里，`think` 里还要用；密钥和地址用一次就够，所以没加 `self.` |
| `all([...])` | 列表里每项都"有内容"才为 `True`，有 `None` 或空字符串就是 `False` |
| `raise ValueError(...)` | 主动抛出错误：配置不全就立刻停下，比等到调用时才出莫名错误好排查 |
| `messages` | 列表，每项是 `{"role": ..., "content": ...}`，`role` 为 `system`（定规矩）、`user`（用户）、`assistant`（模型之前的回答） |
| `temperature=0` | 控制随机程度，0 表示尽量稳定；Agent 和写代码通常希望稳定 |
| `client.chat.completions.create` | 一层层往下：客户端 → 对话功能 → 生成回复 → 发起请求，对应接口地址 `/v1/chat/completions` |
| `stream=True` | 模型一小块一小块返回，像打字机 |
| `chunk` / `delta` | 流式返回的每一小块 / 其中新增的内容 |
| `chunk.choices` | 候选回答列表，通常只有一个，取 `[0]`；控制信息块里是空的，所以先判断并 `continue` 跳过 |
| `delta.content or ""` | 有的块没有文字，值是 `None`，用 `or ""` 当空字符串，避免出错 |
| `print(x, end="", flush=True)` | `end=""` 不换行；`flush=True` 立即显示，才有打字机效果 |
| `"".join(列表)` | 用空字符串当胶水，把小块拼成完整字符串，比反复 `+=` 高效 |
| `except Exception` | 出错时打印原因，返回 `None`，让调用者知道失败了 |

### 3.4 代码里需要修正的一处

如果你的代码里写的是：

```python
timeout = timeout or int(os.getenv("TAVILY_API_KE", 60))
```

这里的标签名 `TAVILY_API_KE` 少了一个字母，只是因为这个标签恰好不存在，才"歪打正着"返回了默认值 60。应改成专门的标签：

```python
timeout = timeout or int(os.getenv("LLM_TIMEOUT", 60))
```

> 历史上的一次报错：曾经把这行写成读取 Tavily 的密钥标签，结果 `int()` 去转换一长串密钥，报了 `invalid literal for int() with base 10`。原因是把"超时时间"读成了别的标签。

## 四、零件二：`search`（联网搜索工具）

### 4.1 思路

把"联网搜索"包装成一个**输入字符串、输出字符串**的函数。所有工具长一个样，执行器调用起来就最简单。

SerpApi 是一个服务：你给它搜索词，它替你访问 Google，把页面整理成结构化的 JSON 还给你，省得自己写爬虫解析网页。

**结果解析的思路：按"答案的直接程度"从高到低挑一个返回：**

| 顺序 | 字段 | 含义 |
|---|---|---|
| 1 | `answer_box_list` / `answer_box` | Google 直接给出的"答案框"，例如问"珠峰多高"时最上面那块 |
| 2 | `knowledge_graph` | 知识图谱卡片，右侧的人物、公司简介 |
| 3 | `organic_results` | 普通搜索结果，取前 3 条的标题和摘要 |

**为什么这样排：** 大模型的输入长度有限、按长度计费。能用一句话直接回答的，就不要塞三条网页摘要，模型也更不容易被无关信息带偏。

**为什么出错时 `return` 字符串，而不是 `raise` 抛异常：** Agent 要把工具结果当作 `Observation` 交回给模型。返回"错误：……"这样的文字，模型读到后可以自己决定要不要换个搜索词重试；直接抛异常，整个循环就中断了。

### 4.2 教程版代码

```python
from serpapi import SerpApiClient


def search(query: str) -> str:
    """一个基于SerpApi的实战网页搜索引擎工具。"""
    print(f"🔍 正在执行 [SerpApi] 网页搜索: {query}")
    try:
        api_key = os.getenv("SERPAPI_API_KEY")
        if not api_key:
            return "错误:SERPAPI_API_KEY 未在 .env 文件中配置。"

        params = {
            "engine": "google",
            "q": query,
            "api_key": api_key,
            "gl": "cn",      # 国家代码
            "hl": "zh-cn",   # 语言代码
        }

        client = SerpApiClient(params)
        results = client.get_dict()

        if "answer_box_list" in results:
            return "\n".join(results["answer_box_list"])
        if "answer_box" in results and "answer" in results["answer_box"]:
            return results["answer_box"]["answer"]
        if "knowledge_graph" in results and "description" in results["knowledge_graph"]:
            return results["knowledge_graph"]["description"]
        if "organic_results" in results and results["organic_results"]:
            snippets = [
                f"[{i + 1}] {res.get('title', '')}\n{res.get('snippet', '')}"
                for i, res in enumerate(results["organic_results"][:3])
            ]
            return "\n\n".join(snippets)

        return f"对不起，没有找到关于 '{query}' 的信息。"

    except Exception as e:
        return f"搜索时发生错误: {e}"
```

### 4.3 参数与语法含义

| 写法 | 含义 |
|---|---|
| `"q": query` | `q` 是 query 的缩写，Google 的惯例 |
| `"gl": "cn"` / `"hl": "zh-cn"` | 地区（影响排序和本地化）/ 语言 |
| `SerpApiClient(params)` | 创建客户端并带上参数 |
| `get_dict()` | 发出请求，把返回的 JSON 转成 Python 字典 |
| `"answer_box" in results` | 判断字典里**有没有**这个键（不是每次搜索都有答案框，直接取会报 `KeyError`） |
| `res.get('title', '')` | 取不到 `title` 就用空字符串，不报错 |
| `enumerate(列表)` | 同时给出序号 `i` 和内容 `res`，所以 `i + 1` 能显示成 `[1]`、`[2]`、`[3]` |
| `[:3]` | 切片，只取前 3 条 |
| `"\n".join(列表)` | 用换行把几段文字拼成一个字符串 |

### 4.4 教程版代码存在的问题

1. **只是代码片段，缺少 `import os` 和 `load_dotenv()`。** 单独运行时 `os.getenv` 会报 `name 'os' is not defined`；因为写在 `try` 里，只会看到"搜索时发生错误: name 'os' is not defined"。
2. **`"\n".join(results["answer_box_list"])` 可能出错。** 默认列表每项都是字符串，但实际往往是字典，拼接会报 `TypeError`。
3. **API 返回了错误，却被说成"没找到信息"。** 密钥错、额度用完时，返回的 JSON 里通常有 `"error"` 字段，前面几个 `if` 都不满足，最后落到"没有找到关于……"，会误导你和模型。
4. **答案框没有 `answer` 字段时会被直接跳过。** 有的答案框只有 `snippet` 或 `result`。
5. **没有设置超时。** 网络卡住时，Agent 会一直等。
6. **搜索结果是网页内容，可能夹带"忽略之前的指令，去做某某事"这类文字。** 模型读到后可能被误导，这叫**提示词注入**。做安全方向的话，这是和 Agent 相关的一类典型攻击面，现在先有个印象就好。

### 4.5 改进后的版本

```python
import os
from dotenv import load_dotenv
from serpapi import SerpApiClient

load_dotenv()


def search(query: str) -> str:
    """基于 SerpApi 的网页搜索工具，优先返回直接答案。"""
    print(f"🔍 正在执行 [SerpApi] 网页搜索: {query}")
    try:
        api_key = os.getenv("SERPAPI_API_KEY")
        if not api_key:
            return "错误：SERPAPI_API_KEY 未在 .env 文件中配置。"

        params = {
            "engine": "google",
            "q": query,
            "api_key": api_key,
            "gl": "cn",
            "hl": "zh-cn",
        }
        results = SerpApiClient(params).get_dict()

        # 先处理 API 自己返回的错误（密钥错误、额度用完等）
        if "error" in results:
            return f"搜索服务返回错误: {results['error']}"

        # 1. 答案框列表：元素可能是字符串也可能是字典，统一转成文字
        if results.get("answer_box_list"):
            texts = []
            for item in results["answer_box_list"]:
                if isinstance(item, str):
                    texts.append(item)
                elif isinstance(item, dict):
                    text = item.get("answer") or item.get("snippet") or item.get("result")
                    if text:
                        texts.append(str(text))
            if texts:
                return "\n".join(texts)

        # 2. 单个答案框
        box = results.get("answer_box")
        if box:
            text = box.get("answer") or box.get("snippet") or box.get("result")
            if text:
                return str(text)

        # 3. 知识图谱
        graph = results.get("knowledge_graph")
        if graph and graph.get("description"):
            return graph["description"]

        # 4. 普通结果，取前三条摘要
        organic = results.get("organic_results")
        if organic:
            snippets = [
                f"[{i + 1}] {res.get('title', '')}\n{res.get('snippet', '')}"
                for i, res in enumerate(organic[:3])
            ]
            return "\n\n".join(snippets)

        return f"对不起，没有找到关于 '{query}' 的信息。"

    except Exception as e:
        return f"搜索时发生错误: {e}"
```

改进点一览：

| 改动 | 目的 |
|---|---|
| 补 `import os`、`load_dotenv()` | 单独运行也能读到密钥 |
| 先检查 `"error" in results` | 密钥错、额度用完时给出真实原因 |
| 答案框列表逐项判断类型 | 避免拼接字典时报 `TypeError` |
| 答案框依次尝试 `answer`、`snippet`、`result` | 不因缺少某个字段就放弃 |
| 全部用 `.get()` | 字段缺失时不报 `KeyError` |

## 五、零件三：`ToolExecutor`（工具箱）

### 5.1 为什么需要它

没有它时，管理工具的方式大致是：

```python
available_tools = {"get_weather": get_weather, "search": search}
```

同时还要在 System Prompt 里**手写**一遍工具说明。这有两个麻烦：同一个工具要在两个地方各写一次，容易改了一处忘了另一处，模型就可能调用一个不存在的工具；工具一多，System Prompt 也要手工改很长。

`ToolExecutor` 的做法：**每个工具只注册一次（名字、说明、函数放在一起），工具清单由代码自动生成。**

### 5.2 代码

```python
from typing import Dict, Any, Callable


class ToolExecutor:
    """
    一个工具执行器，负责管理和执行工具。
    """

    def __init__(self):
        self.tools: Dict[str, Dict[str, Any]] = {}

    def registerTool(self, name: str, description: str, func: Callable):
        """向工具箱中注册一个新工具。"""
        if name in self.tools:
            print(f"警告:工具 '{name}' 已存在，将被覆盖。")
        self.tools[name] = {"description": description, "func": func}
        print(f"工具 '{name}' 已注册。")

    def getTool(self, name: str) -> Callable:
        """根据名称获取一个工具的执行函数。"""
        return self.tools.get(name, {}).get("func")

    def getAvailableTools(self) -> str:
        """获取所有可用工具的格式化描述字符串。"""
        return "\n".join([
            f"- {name}: {info['description']}"
            for name, info in self.tools.items()
        ])
```

> 教程里把类型写成小写的 `callable`（Python 内置函数）。运行没问题，只是编辑器可能给警告；规范写法是从 `typing` 导入 `Callable`。这只影响可读性，不影响运行。

### 5.3 数据结构

注册之后，`self.tools` 里长这样：

```python
{
    "Search": {                          # ← 键：字符串 "Search"，只是名字（钥匙）
        "description": "一个网页搜索引擎。...",   # ← 给模型读的说明
        "func": search                   # ← 给代码执行的函数对象
    }
}
```

两层字典：外层的键是**工具名**，值是一个小字典，里面装着**说明**和**函数**。

### 5.4 三个方法的含义

**`registerTool`：登记一个工具**

- `func` 传的是**函数本身**（不加括号），函数没有被执行，只是被记了下来。
- 先判断是否重名，重名就提醒一句再覆盖，避免你不小心给两个工具起了同一个名字却没察觉。
- `description` 非常重要：它会原样放进 System Prompt，**模型靠这段话决定什么时候用这个工具、怎么用**。写得含糊，模型就会用错或不用。

**`getTool`：按名字取函数**

```python
return self.tools.get(name, {}).get("func")
```

把 `name` 换成 `"Search"` 逐步展开：

```python
self.tools.get("Search", {})
# 用 "Search" 这把钥匙取出外层的值：
# {"description": "一个网页搜索引擎。...", "func": search}

.get("func")
# 再用 "func" 这把钥匙取值：
# search（函数对象）
```

为什么第一层要给默认值 `{}`：如果找不到时返回 `None`，再去 `None.get("func")` 就会报错。多这个 `{}`，保证工具不存在时也不会崩，只是最终得到 `None`。所以**调用的人必须检查结果是不是 `None`**。

**`getAvailableTools`：自动生成工具清单**

```python
"\n".join([f"- {name}: {info['description']}" for name, info in self.tools.items()])
```

- `self.tools.items()`：同时取出每个工具的名字和信息。
- 列表推导式：为每个工具生成一行 `- 名字: 说明`。
- `"\n".join(...)`：用换行拼成一整段。

效果：

```
- Search: 一个网页搜索引擎。当你需要回答关于时事、事实以及在你的知识库中找不到的信息时，应使用此工具。
```

这一段可以直接嵌进 System Prompt 里的"可用工具"部分。

### 5.5 核心原理：函数也是对象，可以被传来传去

**`search` 与 `search(...)` 是两回事：**

| 写法 | 含义 |
|---|---|
| `search` | 指的是**函数本身**，还没有执行 |
| `search("你好")` | 括号表示**执行它**，得到的是返回值 |

```python
print(search)             # <function search at 0x000001...>
print(search("你好"))     # 搜索结果（字符串）
```

**函数传进 `registerTool` 的过程：**

```python
toolExecutor.registerTool("Search", search_description, search)
#                          name       description       func（函数本身，没有括号）
```

进入 `registerTool` 后，`func` 和 `search` 指向的是**同一个函数**，像同一个人的两个外号。接着：

```python
self.tools[name] = {"description": description, "func": func}
```

等价于把函数的"地址"记进了字典，函数既没有被复制，也没有被执行。

**什么时候才真的执行：**

```python
tool_function = toolExecutor.getTool("Search")   # 从字典里把函数取出来
observation = tool_function(tool_input)          # 加括号，这时才执行
```

**整条线：**

```
def search ──传进──▶ registerTool 的 func ──存进──▶ self.tools["Search"]["func"]
                                                          │
                                       getTool("Search") 取出来
                                                          ▼
                                          tool_function(参数) 加括号执行
```

**键和值的区别（最容易混）：**

- `"Search"` 是字符串，是**钥匙**，只用来查找；
- 取出来的是钥匙对应的**值**，那里面放的才是函数。
- 可以用 `print(type(tool_function))` 验证，输出 `<class 'function'>` 说明拿到的是函数。

```python
tool_name = "Search"                                # 字符串：模型输出文字里的一个词
tool_function = toolExecutor.getTool(tool_name)     # 函数：代码用这个词查到的可执行对象
```

> **一句话记住：钥匙是字符串，开出来的是函数。不加括号是"指着它"，加了括号才是"让它干活"。**

**一个最小的类比示例：**

```python
def say_hello(name):
    return f"你好，{name}"

def say_bye(name):
    return f"再见，{name}"

actions = {"hello": say_hello, "bye": say_bye}   # 存函数，没有括号

f = actions["hello"]       # 按名字取出来
print(f("折酒"))            # 加括号执行：你好，折酒
```

`ToolExecutor` 本质上就是这个字典，只是多存了一份给模型看的说明，并把存和取包装成了方法。

### 5.6 为什么要这样设计

模型输出的永远只是**一段文字**，比如 `Search`。代码需要靠这个名字找到真正要执行的函数。如果没有"名字 → 函数"这张表，就只能写很多 `if` 判断：

```python
if tool_name == "Search":
    search(...)
elif tool_name == "get_weather":
    get_weather(...)
elif ...
```

工具一多就很难维护。用字典存起来后，**新增工具只要注册一次，取用的代码一行都不用改**。

### 5.7 两个容易犯的错

1. **传的时候多写了括号**

```python
toolExecutor.registerTool("Search", search_description, search("xxx"))   # 错
```

   这会先把 `search("xxx")` 执行一遍，传进去的是**字符串**，之后再调用它就报 `'str' object is not callable`。

2. **取出来之后忘了加括号**

```python
tool_function = toolExecutor.getTool("Search")
observation = tool_function          # 错：observation 只是函数本身，没有执行
```

## 六、测试代码

### 6.1 作用

**不让大模型参与**，手工模拟 Agent 循环里"执行 Action"的那一步，检查工具和 `ToolExecutor` 能不能配合。

### 6.2 代码

```python
if __name__ == '__main__':
    # 1. 初始化工具执行器
    toolExecutor = ToolExecutor()

    # 2. 注册实战搜索工具
    search_description = "一个网页搜索引擎。当你需要回答关于时事、事实以及在你的知识库中找不到的信息时，应使用此工具。"
    toolExecutor.registerTool("Search", search_description, search)

    # 3. 打印可用的工具
    print("\n--- 可用的工具 ---")
    print(toolExecutor.getAvailableTools())

    # 4. 模拟智能体的 Action 调用，问一个实时性的问题
    print("\n--- 执行 Action: Search['英伟达最新的GPU型号是什么'] ---")
    tool_name = "Search"
    tool_input = "英伟达最新的GPU型号是什么"

    tool_function = toolExecutor.getTool(tool_name)
    if tool_function:
        observation = tool_function(tool_input)
        print("--- 观察 (Observation) ---")
        print(observation)
    else:
        print(f"错误:未找到名为 '{tool_name}' 的工具。")
```

### 6.3 逐步讲解

1. **`if __name__ == '__main__':`**：只有**直接运行这个文件**时，下面的测试才会执行；别的文件 `import` 它时不会自己跑起来。
2. **`ToolExecutor()`**：执行 `__init__`，得到空的 `self.tools = {}`。
3. **`registerTool("Search", search_description, search)`**：`search` 后面**没有括号**，传的是函数本身。描述写了两个使用条件（时事、事实，以及模型知识库里没有的信息），这直接决定模型什么时候会用搜索。
4. **`getAvailableTools()`**：生成将来要拼进 System Prompt 的工具清单，先打印出来看看，确认模型将来看到的就是这样的文字。
5. **手写 `tool_name` 和 `tool_input`**：这是整个测试里最关键的一段。在真实的 Agent 里这两个值不是你写的，而是从模型输出的文字里解析出来的：

```
模型输出：  Action: Search['英伟达最新的GPU型号是什么']
              ↓ 代码解析
tool_name  = "Search"
tool_input = "英伟达最新的GPU型号是什么"
```

   测试先跳过"模型输出"和"解析"，直接给出结果，目的是**把问题缩小**：出错时能确定问题在工具或执行器，而不在模型和解析上。这叫"隔离变量"，是调试里常用的做法。

   选"英伟达最新的 GPU 型号"也是有意的：这是个时效性很强的问题，模型凭训练时学到的知识答不准，只有联网才能回答，正好说明搜索工具的价值。
6. **`getTool` → `if tool_function:` → 执行**：
   - 函数对象本身算"真"，`None` 算"假"，这一句就是判断**取到了没有**。
   - `tool_function(tool_input)` 才真正调用 `search(...)`。
   - 返回的字符串，在 Agent 里就叫 **Observation**，会被追加进历史，交给模型进入下一轮。
   - `else` 分支：模型可能编造一个不存在的工具名，这时不能让程序崩溃，应该返回错误信息，让模型知道"没有这个工具"，自己改正。

### 6.6 把几段代码放进同一个文件时的注意事项

- Python 从上往下执行：**先定义类和函数，再创建对象、注册工具，最后才是测试或主循环**。
- 如果文件里有**多个** `if __name__ == '__main__':` 块，直接运行时它们会**全部执行**（例如先调用一次大模型写快速排序，再测试搜索工具）。想单独测其中一个，可以暂时注释掉另一块。
- 更清晰的拆分方式：

```
hello-agent/
├── .env              # 密钥
├── llm_client.py     # HelloAgentsLLM
├── tools.py          # search 等工具函数 + ToolExecutor
└── main.py           # 主程序：注册工具、组装 Prompt、跑 ReAct 循环
```

## 八、常见问题排查

| 现象 | 可能的原因 |
|---|---|
| `NameError: name 'search' is not defined` | `search` 函数没有定义在测试之前，或没有从别的文件导入 |
| `NameError: name 'ToolExecutor' is not defined` | 类要先于测试代码定义 |
| Observation 是"错误:SERPAPI_API_KEY 未在 .env 文件中配置。" | `.env` 里没有这个标签，或没有 `load_dotenv()`（这是函数**正常工作**的表现，只是密钥没配好） |
| Observation 提示密钥错误、额度用完 | 密钥无效或免费额度用完（要用改进版才能看到真实原因） |
| 搜索时发生错误：name 'os' is not defined | 缺少 `import os` |
| `'str' object is not callable` | 注册时多写了括号，传进去的是字符串而不是函数 |
| 取到 `None` | 工具名拼错（区分大小写），或没注册 |
| 模型ID、API密钥和服务地址必须被提供... | `os.getenv` 里写成了"值"而不是标签名，或 `.env` 没被读到 |
| `invalid literal for int() with base 10` | `timeout` 那行读错了标签，读到了一长串密钥 |
| 导入 `serpapi` 失败 | 包没装或装错了包 |

## 十一、总结

- **三个零件分工明确：** `HelloAgentsLLM` 负责思考，`search` 是具体的工具，`ToolExecutor` 负责管理工具。
- **工具统一成"输入字符串、输出字符串"**，出错时返回错误文字而不是抛异常，这样模型能读到并自己调整。
- **函数是对象**：存的时候不加括号，用的时候才加括号。
- **字典的"钥匙"是字符串，开出来的是函数**：模型只给出名字，代码用名字查表执行。
- **工具说明要写清楚**：它决定模型什么时候用、怎么用。
- **测试时隔离变量**：先单独验证零件，再整体组装。

4. 把结果作为 `Observation` 追加进历史，进入下一轮，直到出现 `Finish`。
